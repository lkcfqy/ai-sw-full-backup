# v0.4 验证记录台实现约定

This is a new data-collection tool, not a new model result. Existing v0.3 results and source snapshots remain historical. Paths below use `/api/studies`.

## Lifecycle and strict inputs

- `POST /api/studies` → `{study}` (201). Body `{title, source_kind, planned_cases, participant_code, note}`. title 1–100, note 0–500; source_kind `self_reported_physical | public_replay | engineering_fixture`; planned_cases integer 1–48; participant_code 1–32 ASCII letters/digits/underscore/hyphen (anonymous). Methods are always `manual` then `kitguard` for each case. No claim of blinded/randomized human study.
- `GET /api/studies` → `{studies:[...]}`; `GET /api/studies/{id}` → `{study}`.
- `POST /api/studies/{id}/cases` (201) → `{study}`. Body `{label, order_id, expected_revision, photo_id, truth, truth_repeat, confirmed_independent:true, source_note}`. Counts `{bolt,nut,washer,bracket}` must be integer 0–100, two independent entries identical. `label` 1–80, source_note 1–500. Use an existing fresh order with a current uploaded photo and **no inspection attempts**. The server seals the current photo SHA, order requirements/revision/evidence epoch/reference hashes and independent counts; repeated photo SHA or order in a study is rejected. Public gallery orders require public_replay. Source declarations are not physical authenticity proofs.
- `POST /api/studies/{id}/freeze` with `{confirmed:true}` → `{study}`. All planned cases must exist and their bindings still match. Saves time, runtime identity and protocol hash. No case editing or deletion API. Before study closure, truth and score are absent from all responses and exports. Registration itself is a declaration, not proof of blinding or two-person independence.
- `POST /api/studies/{id}/cases/{case_id}/start` with `{method:'manual'|'kitguard'}` → `{study,trial}`. One running trial globally per study. Manual must reach a terminal state before KitGuard starts. A method can start once only. Returns trial id, started_at, method, order_id, photo_id, revision, status. Start fixes its denominator and begins server monotonic timing. Reload can resume; process restart marks running trials interrupted with unknown duration.
- `POST /api/studies/{id}/trials/{trial_id}/finish` with `{outcome:'completed'|'failed'|'abandoned', manual_counts?:counts, check_id?:string, note?:string}` → `{study}`. Manual completion requires manual_counts and no check_id. AI completion requires check_id and no client counts. The server reads the actual current check from Store, verifies a single inspection began after start, same image/order/reference/version, actual runtime identity and no cherry-picked retry. `correct` means adjustment required; scoring always compares actual observed counts with sealed truth. Failed/abandoned require a reason. These terminal actions cannot be rewritten/replayed as a different result.
- AI UI: start KitGuard trial → call existing `POST /api/orders/{order_id}/inspect` `{photo_id,expected_revision}` → finish with the returned check_id. On timeout/error, finish failed with message. If capture-binding fails, show error and allow abandoned/failed; never fabricate a result. Page reload during running AI offers read-only refresh and records a returned valid latest check, or explicit failure/abandonment; never auto-retries inference.
- `POST /api/studies/{id}/close` with `{confirmed:true}` → `{study}`. Closes frozen or draft study; any active inspection blocks closure until it commits/terminates. Otherwise running trials are abandoned with a closure reason; pending/missing slots remain not_started. Closure reveals truth and scores. Further mutations forbidden. There is no actual material completion endpoint in this tool.
- `GET /api/studies/{id}/export` downloads complete JSON only after closure. `GET /api/studies/{id}/report.html` downloads a standalone escaped HTML report only after closure. Both include limitations, frozen identity, all planned slots/method denominators, failures and chronology. No export before closure.

## Public response shape

`study`: `{id,title,source_kind,planned_cases,participant_code,note,status:'draft'|'frozen'|'closed',created_at,frozen_at,closed_at,protocol_sha256,runtime_identity,cases:[case],report:null|report}`.

`case`: `{id,label,source_note,order_id,revision,photo_id,photo_sha256,requirements,evidence_epoch,truth_commitment,registered_at,trials:{manual:trial|null,kitguard:trial|null}}`. On closure also `truth` and `truth_nonce` for commitment verification.

`trial`: `{id,method,status:'running'|'completed'|'failed'|'abandoned'|'interrupted',started_at,finished_at,elapsed_ms:null|number,note,manual_counts:null|counts,check:null|actualCheck}`. Response must include order_id/photo_id/revision for the start flow. Internal monotonic timestamps/process nonce and hidden truth are never exposed before closure.

`report`: `{scope,source_kind,planned_cases,registered_cases,methods:{manual:metrics,kitguard:metrics},paired_completed_cases,limitations:[string]}`. Each `metrics`: `{planned,started,completed,correct,wrong,uncertain,failed,abandoned,interrupted,not_started,correct_fraction:null|number,terminal_elapsed_ms:{n,median,max},completed_elapsed_ms:{n,median,max},false_ready:{numerator,denominator}|null}`. `correct+wrong+uncertain+failed+abandoned+interrupted+not_started=planned`; no failures dropped. AI false_ready compares decision ready with truth unequal requirements, denominator registered mismatched cases, including unfinished ones; missing slots have unknown truth and are separately reported. Timing starts after setup/photo registration, not full physical workflow or causal efficiency benefit.

All API mutations honor existing same-origin middleware and use SQLite transactions. All local self-report can be falsified by the operator; hashes prove stored byte consistency, not reality. Manual-before-AI controls one direct contamination path, but no identity isolation or unbiased timing experiment is claimed. Each case is one fixed physical state; changed/added parts need a new case and truth. This release does not measure continuous supplementation success.

## Final integrity and portable evidence additions

- `GET /api/studies/{id}/evidence.zip` is closed-only. It contains `OPEN_ME.html`, `REPORT.html`, `PHOTOS.html`, `STUDY.json`, `MANIFEST.json`, and all frozen target/reference JPEG bytes, deduplicated by SHA. Each image must match its frozen binding. Changed/missing bytes cause 409; the temporary ZIP is removed after delivery. This is portable stored evidence, not photo authenticity or a digital signature.
- Failed/abandoned trial termination and closure are refused while related inspection is active; late valid checks cannot disappear through premature termination. All returned checks and exposure events remain in the export. Explicit failed/abandoned status does not erase an underlying wrong or false-ready output.
- Every method adds `returned_checks` metrics (returned/scorable/wrong-clear/false-ready/uncertain/multiple-attempt/ineligible). Primary outcome categories still add to the planned denominator. Unstarted cases cannot be reported as correct; zero-start correct fraction is null.
- Completed trial finish rechecks the recorder source snapshot and frozen case binding. Public or known-public photo bytes cannot be relabeled as a self-reported physical case by reuploading into another order. Cross-order exposure of the same photo is examined for physical declarations. Source declarations and checks still do not prove scene reality or independent human input.
- Non-engineering completed AI trials require actual MLX backend and frozen identity. Engineered results remain eligible only in explicitly engineering_fixture studies.
- `scripts/verify_study_export.py INPUT --output NEW_PATH` independently checks exported JSON consistency using the standard library. It does not import the recorder's scoring implementation, verify image bytes, authenticate people, or certify the experiment. CLI refuses to overwrite a previous receipt.
