本轮只新增 `kitguard/static/study.html`、`study.js`、`study.css`，并在 `index.html` 添加入口与独立样式引用；未修改原工作台 `app.js` / `styles.css`。

## 已完成的实际操作流程

1. 创建带匿名参与编号、来源声明、预定案例数的批次；区分自行拍摄实物、公开图回放、工程替身。
2. 从没有核验尝试的当前照片工单登记案例。真实数量分两次输入；第二次输入时遮蔽第一次；必须确认独立来源。两次不一致拒绝提交。
3. 登记数达到预定 N 后冻结。冻结前后、关闭之前，接口与页面均不显示真值及成绩；完成登记的表单清除数量输入。
4. 每例先开始人工计时，再完成数量记录或记录失败/放弃；同一批次同时只能运行一个尝试。
5. 人工环节结束后，开始 KitGuard → 调用真实 `/inspect` API 一次 → 绑定返回 check。正常失败也形成不可改写的失败记录。
6. 页面刷新不会重新推理。运行中 AI 只能读取已存在的最新 check，交由服务器校验并绑定，或明确记录失败/放弃。
7. 关闭后展示完整预定分母中的 C/W/U/E 与未开始，细分失败/放弃/服务中断，显示所有案例真值及已返回的错误检查；返回错误后选择放弃也不能隐藏该错误。
8. 仅关闭后支持真实 JSON 与独立 HTML 下载。此界面从不调用工单 `/complete`，不记录物理出库或实物完成。

计时来自服务端开始到结束；并非拍摄、准备和完整实物作业时长。此工具不声称随机实验、盲测、两人独立标注或连续补件成功率。页面与报告卡片均明确显示来源边界。

## 实施边界

- 所有字符串进入模板前 HTML 转义；图片/API 链接的 ID 编码；新页面没有内联脚本或内联事件处理器，遵守现有 CSP。
- 所有提交期间禁用按钮和表单；异步 AI 刷新后只读恢复，无法通过界面再次推理。
- 本地操作者仍可伪造来源或独立计数声明；哈希证明保存字节的一致性，不认证现实。另一个工作台仍能泄露 AI 结果，服务器负责拒绝被污染的登记或完成。
- 本轮没有访问生产数据库、调用 GPU、改变 v0.3 冻结评测或旧交付目录。
