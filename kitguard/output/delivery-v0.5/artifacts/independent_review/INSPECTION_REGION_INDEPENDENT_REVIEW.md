# 操作者检查区域：独立设计与反例审查

2026-09-27 00:30（韩国时间）。完成对设计、后端与独立反例的复验：**54/54通过，Ruff通过**。仅用工程合成照片、隔离 SQLite 与确定性观察器；不调用 GPU，不改变 v0.4 的20+1作者计数真值、分母或归档。审查由另一个 Codex AI 代理进行，不是独立人类审计。

## 实现前必须保持的约束

1. 范围声明限定“本次工单计数包含什么”，不能认证操作者没有遗漏框外物体。根图指本系统已保存的去元数据、纠正方向的完整 JPEG，不能称相机原文件。模型空间点、身份检查裁剪和建议补拍区仍属于当前输入视图坐标；UI不能直接叠到根图。
2. 选区坐标、声明及 revision/current photo/epoch 必须严格验证；同范围幂等请求也要先验证这些令牌。active inspection、已完成工单与任意未关闭研究中的已登记案例都阻止区域修改。保存事件是范围选择，不是新拍摄。
3. field 的登记/冻结与范围修改必须在同一 SQLite 写事务序列中检查，不能先读研究列表、后独立改工单。若登记先完成则拒绝变更；若变更先完成，旧 photo 的登记应拒绝。draft 已登记即锁定，否则会把不可编辑案例变成过期绑定。
4. 所有派生视图直指工单内完整根照片。拒绝自身循环、根图反指视图、视图指视图、跨工单及参考图来源。检查开始、提交、完成和两种证据 ZIP 都需验证实际根图/视图 SHA，不能只验证模型所见的 crop。
5. 同根的区域变化不能扩增物理样本 N、清空补证预算或声称“新照片解决了问题”。反馈不能复用另一坐标系的旧区域。对系统已知字节还需考虑 `new.source_sha256 == known.root.sha256` 的重上传链：已观察 crop 后把完整根 JPEG 重新上传且再次编码，normalized SHA 可能改变，不能仅靠新 normalized SHA 判未曝光。这不承诺识别任意外部裁剪、转码或相似场景。
6. 导出同时携带原有根图与精确派生图、尺寸/范围/编码方法/声明、范围历史、原公开来源及许可。关闭研究之后可在普通工单再选范围，但旧研究仍要引用旧不可变视图，不能借用最新范围。哈希/几何通过仅说明内部一致，不认证物理真实或声明完整。

## 独立反例与修复复验

`tests/test_inspection_region_review.py` 覆盖严格整数及 NaN/Infinity/超大/布尔输入，过期三个并发令牌、旧工单版本照片、跨单/参考/历史根引用、同范围幂等、恢复整图原字节、重新裁剪只读根图、活跃推理、旧 ready 失效、根图在推理中或完成前篡改、两个 ZIP 的字节绑定、同源反馈/补证预算、draft/frozen锁定、登记写事务竞态、非法 lineage、跨单曝光与根 JPEG 重上传、同源不同 crop 不增加研究分母。

实现过程中发现并由后端实现者修复、独立复验的两项缺陷：

- NaN/Infinity/-Infinity 被输入类型拒绝后，默认错误详情回显非有限浮点，错误响应序列化反而返回500。现在安全错误响应返回422且不修改订单。
- 原先仅分别验证根图和派生图 SHA，合法但篡改的坐标/尺寸/坐标系/编码声明仍能通过核验。现在按根图与声明重建派生 JPEG，精确核对字节、尺寸及版本，四类篡改反例均返回409。

另外实际复验：两个标签页携带同一旧令牌只能提交一个新视图；根图在生成裁剪后、事务提交前被替换时拒绝且删除未提交派生文件；field案例登记持写事务时另一线程的区域变更在登记提交后拒绝；已关闭study的合法旧范围仍能导出，篡改冻结scope但不改两个图片及SHA时仍拒绝导出。后者由 `studies.export` 按case的历史photo而非工单最新photo重建并比对，避免关闭后合法重选破坏旧证据。

同源范围改变允许专门的 `inspection_scope_changed` 提示，但其物理新证据/物理动作字段为false，改变量与“已解决的不确定项”为空；它不是补拍改善。两种ZIP的成功路径均核对完整根 JPEG、派生 JPEG、各自SHA和scope快照，没有依赖视觉相似性。

复验命令：`.venv/bin/pytest -q tests/test_inspection_region_review.py --junitxml=test-results/inspection-region-independent-review.xml`。54例通过，耗时1.63秒；唯一警告为现有 Starlette/httpx 弃用提示。测试源SHA-256：`22185b7d3f973fdb2ff5445e87f7b81df46676b3c06de9db3e403af3055fee36`；JUnit SHA-256：`dfb9c2fa7a67c9d6e215eb15247ed7a73adf998ca9047f0420a159cf89016f36`。
