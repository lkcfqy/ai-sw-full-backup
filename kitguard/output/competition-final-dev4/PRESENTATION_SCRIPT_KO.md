# dev4 · 6분 발표와 2분 질의 준비

준비용 원고입니다. 실제 발표 리허설이나 심사위원 질의를 수행했다고 주장하지 않습니다. 9장 슬라이드 및 0.9.0.dev4 소스와 함께 사용합니다. 사람 0명, 실물 완료 0건, 새 정확도 분모 0건을 유지합니다.

**0:00–0:40 / 1–2장.** 안녕하세요, 해피 팀의 KitGuard입니다. 사진 속 부품 수량만 맞아도 충분하지 않습니다. 주문 BOM이 바뀌었는데 옛 사진 검사 결과를 다시 사용하면, 현재 요구와 관계없는 결론이 남을 수 있습니다. 저희는 사진과 BOM을 현재 주문 버전에 묶어 검토하고 증거까지 저장합니다. 공장 사용자와 수요는 아직 검증하지 않은 가설입니다.

**0:40–1:25 / 3장.** 사용자는 현재 자료의 검토라는 목표를 맡깁니다. 시스템은 주문 ID, 버전, 증거 epoch와 사진 ID를 먼저 확인합니다. 실제 사진 관찰은 로컬 MLX 모델이 수행합니다. 이후 명시적 규칙이 수량 차이, 추가 자료 요청 또는 일치 기록으로 분기합니다. 자유로운 범용 계획이나 자동 출고 Agent는 아닙니다.

**1:25–2:35 / 4장과 실제 화면.** 자신의 사진·BOM 목표와 공개 3개 시나리오 모두 실행할 수 있습니다. 공개 시나리오는 수량 차이, 작은 부품 불확실성, 사전 선언한 R1에서 R2로의 변경입니다. 변경은 모델이 정답을 맞추려고 BOM을 고치는 것이 아닙니다. R1을 무효화한 뒤 동일 사진의 재사용을 표시하고 새로운 R2 추론을 실행합니다. 브라우저를 닫아도 실행은 계속되며, 저장된 도구 결과와 원본 사진을 열어볼 수 있습니다.

**2:35–3:30 / 5–6장.** 실행 전에 다섯 개 기계 과제와 예상 흐름을 고정했습니다. 네 번의 새 MLX 검사를 실행했고, 물리적 출고 주문은 모델 호출 전에 거절했습니다. 같은 실제 관찰에서 버전 확인만 생략한 CPU 대조는 옛 ready를 계속 사용하는 문제를 보였습니다. 이는 버전 보호 기능의 제한된 검증이며, 경쟁 제품 비교나 사람의 작업 시간 개선 실험이 아닙니다.

**3:30–4:25 / 7장.** 좋은 결과만 선택하지 않았습니다. 기존 51장 평가에는 41개 정확, 3개 오류, 7개 미확정과 3개 false-ready가 남아 있습니다. LOCO24는 별도 도메인의 제한된 결과로 합치지 않습니다. 연구 후보 중 기준을 만족하지 못한 방법은 제품에 채택하지 않았습니다. 모르면 자료를 요구하고, 실패하면 입력과 오류를 보존하며, 실물 완료는 승인하지 않습니다.

**4:25–5:20 / 8장.** 기존 M5 Pro 64GB와 프로젝트 내 모델을 사용합니다. 외부 GPU나 클라우드 모델 호출은 없습니다. 네 기계 과제의 서버 자율 실행은 약 20–49초입니다. 업로드와 사람 작업 시간은 제외한 숫자입니다. 슬라이드의 시간당 처리량은 이 실행 시간과 점유율을 사용한 계산 가정으로, 연속 부하 실험이나 SLA가 아닙니다. 도입 지원 모델은 가설이며 고객, 가격과 매출을 검증하지 않았습니다.

**5:20–6:00 / 9장.** 현재 단계는 반복 실제 사용자 효과를 증명한 Pilot이 아니라, 끝까지 동작하는 Level3 MVP입니다. 다섯 최종 자료의 버전과 증거를 맞추었고, 기존 코드와 AI 도움을 공개합니다. 사진 판정의 한계까지 포함해 재현 가능한 현재 자료 검토 흐름을 보여드리겠습니다.

## 예상 질문

**왜 Agent인가?** 사용자가 검토 목표를 맡기면, 입력 확인→실제 관찰→조건 분기→도구 실행→저장까지 수행합니다. 목표와 기억은 버전 바인딩/실행 기록입니다. 계획은 규칙 기반이며 자율성 범위를 숨기지 않습니다.

**기존 제품과 차이는?** 계수, 로컬 배포, 다단계 흐름은 기존 제품에도 있습니다. 검증한 범위는 사진/BOM/버전 바인딩, 옛 결론 무효화, 불확실성과 실패 보존, 내보내기의 연결입니다. 공식 자료만 조사했고 기존 제품을 실행해 우월성을 입증하지 않았습니다.

**5/5가 정확도인가?** 아닙니다. 미확정과 거절까지 미리 정한 기계 흐름에 도달했다는 뜻입니다. 세 장 모두 노출된 개발 사진입니다. 새 사진 정확도 분모를 늘리지 않습니다.

**어떻게 오류를 줄였나?** 이번 변경은 옛 버전 결과 재사용을 막는 소프트웨어 제약입니다. 시각 모델의 기존 세 오류를 고친 것은 아닙니다. 버전 바인딩을 생략한 대조의 같은 관찰에서 차이를 확인했습니다.

**작은 부품이나 세부 SKU도 되나?** 현재 네 종류의 거친 범주만 다룹니다. 나사 규격, 재질, SKU와 숨겨진 물체를 보장하지 않습니다. 불확실하면 추가 자료를 요구합니다.

**사업성과 비용은?** 설치·도입 지원이라는 가설은 있으나 고객, 지불 의사와 가격은 검증되지 않았습니다. 새 물품 구매와 외부 모델 호출은 없지만, 전기와 보유 하드웨어 비용을 0이라고 가정하지 않습니다.

**인터넷 없으면?** 준비된 환경과 모델에서 로컬 추론·주문·증거를 사용합니다. 새 환경의 의존성과 모델 다운로드는 별도 단계입니다. 한 서비스/한 추론 작업을 사용하며, 공개 네트워크 운영은 검증하지 않았습니다.

**영상은 실제인가?** 실제 브라우저 시간 샘플입니다. 샘플 사이 원래 화면을 정지 상태로 유지하고 모든 모델 기다림을 남겼습니다. 연속 원생 녹화라고 주장하지 않으며 한국어 음성은 합성입니다.

**왜 실물이나 사용자가 없는가?** 이번 개발 범위는 기존 하드웨어로 끝까지 돌아가는 디지털 자료 검토입니다. 실제 사람 효과와 현장 신뢰성은 0/미검증으로 공개합니다.
