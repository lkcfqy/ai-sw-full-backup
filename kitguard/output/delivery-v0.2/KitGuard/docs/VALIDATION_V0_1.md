## 真实本地模型链路

Apple M5 Pro / 64GiB统一内存 / macOS26.6.2，MLX-VLM0.7.3，固定的 Qwen3-VL-8B-Instruct 8-bit 模型。约9.87GB、17个仓库文件完成下载和大小检查，SHA-256存档；大文件与上游 LFS SHA-256一致。

本轮4个工程案例的实际结果：

| 输入 | 结果 | 实测用时 |
| --- | --- | ---: |
| 韩语：螺栓减1、垫圈加1，初始各1 | 正确生成0/1/2/1提案 | 首次端到端5.798s，推理3.247s |
| 中文：螺栓改成2个，其他不变 | 正确生成2/1/1/1提案 | 端到端1.929s |
| 中文：螺栓100个 | 返回澄清，拒绝越界，不截成3 | 端到端1.694s |
| 明确标注的合成测试图，经真实创建订单→上传→inspect API | `backend=mlx`，四类数量均为null，转人工，未完成订单 | 图像API5.465s |

首次模型加载2.100s。MLX报告分配内存峰值10.913GB（十进制，来自 `mx.get_peak_memory()`）；macOS进程最大RSS为10,766,778,368字节。它们是不同口径，均不是整个系统内存使用量。少量短指令与合成图片的耗时不代表所有真实照片、多参考图或并发情况下的性能。

完整输入、输出、时间与运行脚本位于公共模型目录 `~/Downloads/AI-Models/verification/kitguard_smoke_result.json` 和 `kitguard_smoke.py`。测试使用临时订单数据；生产工作台保持空白，等待真实订单。

发现并处理的兼容问题：此固定社区仓库的索引仍列旧的4分片名称，实际量化权重为2个分片。保留上游原文件和哈希，适配器检查已验证的实际分片，MLX-VLM使用其自身的权重文件回退加载路径。详见公共模型目录的来源说明。测试后，已批准前提下才变更订单的语义还通过代码生成的“未应用提案”说明固定，避免模型措辞暗示已经修改。
