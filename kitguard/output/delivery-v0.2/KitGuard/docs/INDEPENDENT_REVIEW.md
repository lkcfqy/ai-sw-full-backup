## 2. 五个最影响竞争力、可处理的缺口

### P0 — 真实视觉有效性仍缺证据，公开数据又可能与产品范围不一致

**现有证据。** `docs/VALIDATION.md` 的真实图像链路案例是显式合成图被转人工；这验证了真实 MLX 调用和保守处理，未验证能正确核验一个实拍套件。当前四类是 bolt/nut/washer/bracket，每类需求 0–3、总数 1–12。`PUBLIC_DATA_PLAN.md` 已承认 LOCO screw_bag 的长短螺丝区分不在当前分类内，公开静态图也没有真实补件轨迹。

**修复重点。** 完成根任务正在做的真实图像评测后，冻结能够支持的类别/摆放范围，保留全量失败。数据许可、类别映射、真值来源、原图划分及排除条件与结果一起交付。对每类宣称支持的物件，给出真实图片上的可复核实例；不适配的数据不硬套到四类。若仅公开静态图可用，就把成果称为“公开实拍数据静态核验＋明确标注的流程回放”，不要声称已验证真人补件收益。

**关闭条件。** 一个评审者能从数据清单定位每个测试原图、授权/许可、独立数量标签、冻结配置和逐例输出；全部预定 case_id 均有成功或失败记录。公开图中的真实数量、人工构造的订单和模拟事件分别标注。至少有真实可判定输入走到正确的待确认状态，另有实拍不符输入被正确指出差异；不能仅靠全部转人工来满足“安全”。以上是证据完整性和功能覆盖门槛，不是预设某个准确率。

### P1 — 补证有状态上限，但“上次建议是否带来有效新证据”尚未被明确核验

**现有证据。** 本轮读取的 `LocalVision.observe` 只接收最新图片与参考图；目标数量被正确隔离。`app.decide` 使用同版本历史检查限制补证轮次，但模型不读取上次观察/请求，记录也没有显式的 `requested_action → new_evidence → resolved/unresolved` 关系。当前可以准确描述为“根据本次观察选择下一步、保留历史、限制重试”，不宜描述成已经判断上次动作执行效果的规划器。

**修复重点。** 保留视觉计数与 BOM 目标隔离；增加受控的补证上下文和服务器端反馈记录。对新图明确说明：此前哪一项证据不足、上次请求是什么、当前不足是否消除、下一步为何改变。需要的是可观察的反馈闭环，不是更多自由文本推理或展示模型隐藏思维。

**重要边界。** “上次数量＋补 X 件/取出 X 件”会间接暴露目标，不能同时塞给视觉观察器。视觉上下文可限定为上次视觉问题、未知类别、`separate/recapture` 请求、区域、轮次；数量差异与补件结果由控制器在取得独立新计数后比较。没有前后两张相关实拍图时，只能说当前证据是否充足，不能声称物理动作确实执行。

**关闭条件。** 第 3 节的行为案例均保留请求、相关图片、观察和结果关联；错误操作不能被当成正确执行；改版和参考变动仍使旧结果失效。工程夹具验证控制器分支，真实连续照片验证视觉/物理部分，两种证据分别报告。

### P1 — 对人工清单或一次 VLM 的实际增益尚未成立

**现有证据。** `REAL_WORLD_VALIDATION.md` 与最终方案列出了比较方法和目标，但没有实际比较结果。67 个事务/输入测试不是减少漏配或节约时间的证据；4 类、最多 12 件的任务也可能人工更快。

**修复重点。** 用同一个冻结数据集比较同模型的一次观察与完整 KitGuard；增加“同样托盘/已确认结构化订单＋人工清单”的可操作对照。自然语言变更的设置时间和结构化订单后的核验时间分开。方法共享起始图片、订单和可用信息，补证预算固定；将错误可确认、正确完成、误拦、人工接管、模型耗时分别列出。若没有真实参与者，不编造人工时长，仅保留可实施的实验协议。

**关闭条件。** 比较脚本/操作协议、冻结 case_id、每例真值、每种方法输出和完整失败清单可复核；任何“更准确/更快”的句子都能指向对应实测及口径。未显示收益的项目改为能力展示或限制，不以“拒绝全部”赢错误率，也不以劣化基线制造优势。

### P1 — 评委尚拿不到一份可复现、可快速理解的成果包

**现有证据。** 当前 UI 的 JSON 导出保留了状态与历史，但不包含图片；检查记录包含模型标签，尚不能单凭每次检查自身定位到模型 revision、提示/协议版本及当时参考图集。固定模型与依赖信息存在项目/公共模型目录，尚需在评审包中建立一致索引。正式报告、技术说明、视频和幻灯片尚未成品。

**修复重点。** 为核心任务生成允许再分发的证据包：图片/来源清单、版本化订单、观察、动作、反馈、工具结果、完成回执、模型/代码/协议标识。即使以人工整理的目录实现，也比新增复杂导出服务更直接。提交包只包含本项目与获准材料，不把上层目录的个人报名/资格文件混入源码包。围绕同一条任务制作五项正式成果，所有数字来自同一结果清单。

**关闭条件。** 在全新临时数据目录按 README 启动，执行一条新工单任务，重启后能读取证据及完成历史；评审包换目录后图片链接仍有效。视频实际时长 ≤180 秒、报告正文 ≤5 页、技术说明 1 页、幻灯片 ≤10 页；至少一次独立复核文件内容、运行命令、许可证和数字一致性。Mac/MLX 的运行边界须明确，不声称已验证 Windows/RTX 3080 环境。

### P0（资格未决）— 正式开发期与赛前实现的关系不能靠来源披露自行豁免

**现有证据。** 官方基本开发期为 2026-09-29 至 2026-10-06；本项目已如实记载 2026-09-26 开始实现。r1 个人同意书明确包含赛前开发条款，且旧版本已有同样条款，详见第 4 节。当前没有记录显示主办方已允许将这批赛前代码作为本届正式新开发作品。

**处理重点。** 继续按用户授权开发并保留真实时间/版本；在最终资料中区分既有资产、赛前原型与正式赛期新增工作。比赛接纳性列为未决，不能改写日期，也不能将“披露了来源”表述为“已获准”。完整报名仍需要实际资格证明、地址和本人签署等用户材料；本审查不替用户确认或提交。

**关闭条件。** 使用正式公布规则或可留存的主办方认定解决赛前项目代码的使用范围；据此整理最终声明。没有这一依据时，该项保持未决。这是参赛资格门槛，不是对源代码是否可继续开发的许可判断，也不是本报告擅自认定已取消资格。

## 3. 历史补证的具体可验证验收例

以下案例的数量仅是明确输入，不是准确率目标。可以用工程夹具验证状态分支，但产品效果必须用真实图像重新验证。每次新观察仍以最新图为准，旧计数不能填补新图里的 `null`。

| 案例 | 输入/前序事件 | 应观察到的结果 |
| --- | --- | --- |
| 分开后发现缺件 | R1 需求 washer=2；第一次图重叠使 washer=null，请求 separate；第二次相关实拍图已分开且实有 washer=1 | 反馈说明此前重叠已解除；根据独立新计数从补证转为 correct，并要求补 1 件后新图核验。不得因“执行过分开”直接 ready。 |
| 无效补证 | 上次请求分开放置；新图仍有同处遮挡或没有足够新信息 | 保留未解决问题及新证据关联；请求更具体的有效视角/分放或达到预算后转人工；不能断言动作已完成。图片哈希相同只能证明字节相同，不能据此推断真实现场没变化。 |
| 执行了错误操作 | 上次代码根据新计数提示补 washer；下一张相关实拍图显示 nut 增加、washer 仍缺 | 当前差异仍 correct，同时指出多出的 nut 与缺少的 washer。不能把操作者声明“已补件”作为成功依据。数量目标和补件差值仅给服务器判定，不给视觉计数。 |
| 新图推翻旧观察 | 旧图某类清楚计为 2；新图同类被遮挡 | 新观察应为 null/需补证；不能沿用旧的 2 填空，也不能完成。 |
| 反馈期间订单变更 | R1 的补证/补件任务未结束时批准 R2；迟到的 R1 观察回传 | R1 响应不能使 R2 ready；旧反馈保留为历史，当前待处理原因和目标使用 R2。 |
| 参考图被更换 | 已有旧参考下的检查/动作；参考图替换后再提交新图 | 旧有效性立即撤销。必须能从记录辨认新观察使用的参考版本，不能把旧参考下的结论当成当前完成依据。 |
| 受限预算与恢复 | 一项证据问题经两轮追加仍不足；随后操作者提供真正清晰新图 | 超预算时必须转人工、不能无限循环；新图仍可独立核验。预算适用单位（同一问题/同一订单版本）须公开且与实现一致，不能说“连续失败三次”却累计一生所有失败。 |

建议的反馈结构是：`previous_check_id`、`previous_photo_id`、上次视觉请求、当前 `photo_id`、已解决/未解决证据项、下一步选择原因和相关版本标识。仅记录可核对事实，不让模型自行声明数据库写入成功。若比较前后照片，明确区分两张目标图与参考图，防止把前图中的零件计入当前库存。

## 5. 冻结版的产品验收门槛

这些是可执行的交付闸门，不是人为指定识别准确率，也不是官方评分标准。

1. **事实闭环。** 至少一条当前支持范围内的真实输入任务完整到达“输入→实际本地观察→代码差异→新证据/再检查→人工明确确认→已提交状态回读”。每一步都有原始记录。若缺连续实拍证据，明确把静态核验与模拟流程分成两项验收，不混称真人闭环。
2. **安全状态。** 冻结的改版、换图、换参考、迟到响应、无效 JSON、无模型、取消/超时、重复完成、重启案例均满足当前合同；任一状态错误可绕过完成检查，都应阻断候选版本。视觉识别误差另行报告，不从这些确定性通过率推断工业零风险。
3. **有用且诚实。** 支持范围内至少能展示真实正确观察及真实差异识别；报告完整冻结集里的计数、错误 ready、拒绝/人工处理和延迟。不能仅展示最优样本，也不能以大比例接管掩盖无法完成任务。
4. **反馈可核对。** 第 3 节的任务轨迹能回答“上次请求了什么、拿到了什么新证据、哪些问题解决/未解决、为什么进入下一步”；数字和批准状态由工具读回，不让文字说明冒充执行结果。
5. **可复现。** 源码/依赖/模型 revision/协议版本/数据来源有固定标识；干净临时数据目录可启动、任务可重做、重启后历史可读取、迁移后照片可访问。已验证平台和未验证平台明确分开。
