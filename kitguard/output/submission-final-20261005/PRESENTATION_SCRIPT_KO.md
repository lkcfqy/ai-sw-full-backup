# KitGuard 6분 발표 · 2분 질의 준비

팀 **해피** · 제품 **0.9.0.dev4** · 문서 수정 **2026-10-05 KST**

9장 슬라이드와 현재 dev4 시연에 맞춘 원고입니다. 아래 시간은 리허설 목표입니다. 시연은 대기 중 설명을 이어가고 실제 결과가 저장된 뒤 화면을 확인합니다. 세 시나리오 영상은 약 177초이므로 6분 발표에서 영상 전체와 장문의 설명을 함께 넣지 않습니다. 현재 실행 또는 실제 저장 기록 중 무엇을 보여주는지 밝힙니다.

## 6분 발표 원고

**0:00–0:40 / 1–2장 · 문제와 목표**

안녕하세요. 해피 팀의 KitGuard입니다. 사진 속 부품을 세는 것만으로는 현재 주문을 검토할 수 없습니다. 예를 들어 사진 검사는 나사 두 개로 일치했는데, BOM이 세 개로 바뀌었다면 이전의 “일치”는 현재 주문의 결론이 될 수 없습니다. 저희는 사용자가 맡긴 현재 사진과 BOM을 버전에 묶고, 실제 관찰부터 검토 기록과 증거 내보내기까지 이어지는 로컬 작업 흐름을 만들었습니다. 현장 수요는 아직 검증할 가설입니다.

**0:40–1:25 / 3장 · Agent 실행 구조**

사용자가 “현재 자료를 검토해 달라”는 목표를 맡기면 주문 ID, revision, evidence epoch, photo ID를 확인하고 수락한 입력을 고정합니다. 로컬 Qwen 모델이 실제 사진을 관찰하고 프로그램은 수량 차이, 추가 자료 요청, 일치 기록 중 필요한 도구를 실행합니다. 목표와 실행 이력은 저장되고 입력이 바뀌면 오래된 목표를 거절합니다. 계획과 도구 선택은 규칙 기반입니다. 핵심은 현재 입력에 책임 있게 연결된 실행입니다.

**1:25–2:35 / 4장 · 실행과 증거 화면**

자료 주문에서 현재 사진과 BOM을 확인하고 “자율 검토”를 시작합니다. 차이가 보이면 어떤 수량이 다른지 기록합니다. 작은 부품을 확정하지 못하면 수량을 억지로 채우지 않고 추가 자료를 요청합니다. 공개 영상의 세 번째 시나리오는 미리 정한 R1의 나사 요구량 3에서 R2의 요구량 2로 변경합니다. 변경이 승인되면 이전 검사는 무효가 되고 같은 공개 사진임을 표시한 뒤 실제 새 추론을 실행합니다. 사진 속 부품을 보충한 시연이 아닙니다.

브라우저를 새로고침해도 실행을 이어 확인할 수 있습니다. 완료 후 사진, 당시 BOM, 모델 결과와 도구 단계가 든 증거를 내려받아 오프라인으로 열 수 있습니다. 실패한 입력과 오류도 남깁니다.

**2:35–3:30 / 5–6장 · 사전 고정 과제와 대조**

실행 전에 다섯 기계 과제의 입력과 예정 흐름을 정했습니다. 수량 차이, 추가 자료, 일치, 개정 후 오래된 목표 거절과 새 검사, 실물 주문 범위 거절입니다. 세 장의 알려진 사진으로 네 번 실제 MLX 검사를 수행했고 다섯 흐름을 충족했습니다. 이는 100% 사진 정확도가 아닙니다.

대조 과제에서는 먼저 나사 요구량 2의 일치 결과를 저장한 뒤 요구량을 3으로 바꿨습니다. 같은 실제 관찰에서 버전 결합만 생략한 CPU 대조는 이전 ready를 계속 사용했습니다. KitGuard는 오래된 목표를 거절하고 새 검사로 차이를 기록했습니다. 이 대조는 버전 보호 기능을 설명합니다. 경쟁 제품이나 사람의 업무시간을 비교한 실험은 아닙니다.

**3:30–4:25 / 7장 · 모델 결과와 안전 경계**

시각 모델의 한계도 그대로 공개합니다. 기존 51장 평가에서 기본 방식은 정확 41, 오류 3, 미확정 7입니다. 같은 모델의 반복 확인도 같은 오인을 반복할 수 있습니다. 별도 LOCO24는 같은 공개 데이터 도메인의 수량 구성 평가로 정확 23, 오류 0, 미확정 1이며 기존 51장과 합치지 않습니다. 이번 목표·버전 기능이 기존 세 오류를 고친 것은 아닙니다.

현재 결과는 사진 자료의 검토 보조입니다. 실물 완료를 자동 승인하지 않고, 모르면 자료를 요청하며, 실패하면 입력과 오류를 보존합니다. 해시는 증거 파일의 연결을 확인하며 사진의 현장성이나 진실값을 인증하지 않습니다.

**4:25–5:20 / 8장 · 실행 환경과 도입 가설**

기존 M5 Pro 64GB에서 고정된 로컬 모델을 실행했습니다. 제품의 사진 추론에 클라우드 호출이나 외부 GPU를 사용하지 않았습니다. 네 기계 과제의 서버 실행은 약 20–49초였으며 사진 등록과 사용자 작업은 제외한 시간입니다. 시간당 처리량은 이 네 시간과 점유율로 계산한 가정입니다. 연속 부하나 사람의 효율을 측정한 결과는 아닙니다.

자료 권한을 확보한 팀의 사진/BOM 검토와 설치 지원을 도입 가설로 생각합니다. 고객, 가격, 지불 의사와 매출은 아직 검증하지 않았습니다. 다음 검증은 새 자료의 독립 진실값과 반복 검토 품질을 확인하는 것입니다.

**5:20–6:00 / 9장 · 완료 상태와 공개**

현재 단계는 끝까지 실행되는 자료 검토 MVP입니다. 같은 버전의 보고서, 기술 설명, 소스, 영상과 발표자료를 준비했습니다. 실제 개발은 9월26일 시작했고 기존 원형의 재사용과 대회 기간의 추가 개발을 공개합니다. Codex를 구현·테스트·자료 제작에 광범위하게 사용했습니다. 실제 사용자 참여와 실물 완료는 각각 0입니다. 현재 자료에 연결된 실행과 그 한계까지 확인할 수 있는 KitGuard를 보여드리겠습니다. 감사합니다.

## 2분 질의 준비

한 답변은 15–25초를 목표로 합니다. 질문받은 항목의 근거를 먼저 말하고 자세한 수치는 해당 화면·보고서에서 확인합니다.

**왜 Agent인가요?**

사용자가 현재 자료 검토라는 목표를 맡기면 입력 확인, 실제 사진 관찰, 결과에 따른 도구 실행, 저장과 증거 정리까지 이어 수행합니다. 목표와 기억은 버전 결합 및 실행 기록으로 구현했습니다. 계획은 규칙 기반이며 자유로운 범용 작업 계획을 검증한 것은 아닙니다.

**다섯 과제 모두 성공했다면 정확도 100%인가요?**

다섯 개는 미확정과 범위 거절을 포함한 사전 지정 흐름입니다. 알려진 사진 세 장에서 네 번 검사했고 새 이미지 정확도 분모는 0입니다. 별도 사진 평가의 기본 결과는 정확 41·오류 3·미확정 7/51입니다.

**실제 어떤 오류를 막았나요?**

요구량 2의 이전 일치 결과를 요구량 3으로 바뀐 주문에서 재사용하는 일을 막았습니다. 같은 저장 관찰의 버전 결합 제거 대조로 기능을 확인했습니다. 현재 시각 모델의 세 가지 오인 자체를 고친 것은 아닙니다.

**같은 사진에서 BOM을 바꿔 일치시킨 것 아닌가요?**

공개 영상의 3→2는 실행 전에 정한 모의 개정이며 수정 승인과 같은 사진의 재사용을 표시하고 실제 새 추론을 실행합니다. 실물 보충을 주장하지 않습니다. 별도 대조는 반대로 2→3을 사용해 옛 일치가 무효가 되고 새 차이가 남는 것을 보여줍니다.

**기존 제품과 무엇이 다른가요?**

계수와 로컬 시각 흐름은 기존 솔루션에도 있습니다. 검증한 구현은 현재 사진/BOM/버전 고정, 옛 결론 무효화, 불확실성과 실패 보존, 증거 내보내기의 연결입니다. 기존 제품을 실행해 성능 우위를 입증하지 않았습니다.

**오류가 있는데 어떻게 사용할 수 있나요?**

자료 검토 보조 범위로 사용합니다. 네 종류의 거친 수량을 관찰하며 세부 SKU, 규격, 재질과 가려진 물체를 보장하지 않습니다. 결과와 한계를 함께 보존하고 실물 출고는 승인하지 않습니다. 현장 도입에는 권한을 확보한 새 자료와 독립 검증이 필요합니다.

**LOCO24의 95.8%를 현재 정확도로 보면 되나요?**

24장은 같은 공개 도메인의 제한된 조합 평가입니다. 총 6개·bolt 2개·bracket 0개이고 nut/washer 구성이 달라집니다. 정확 23·오류 0·미확정 1을 그대로 별도 보고하며 기존 51의 세 오류를 상쇄하지 않습니다.

**영상은 실제 실행인가요?**

실제 브라우저 화면을 시간에 따라 추출했고 화면 사이 간격과 모든 모델 대기를 유지했습니다. 한국어 내레이션은 합성 음성입니다. 세 시나리오 서버 실행은 137.071초, 영상은 약 177초이며 연속 화면 녹화로 표시하지 않습니다.

**비용과 사업성은요?**

새 실물 구매와 외부 모델 호출 없이 기존 장비로 개발했습니다. 전기나 보유 하드웨어 비용을 0으로 계산하지 않습니다. 설치·도입 지원은 가설이고 고객, 가격, 수요와 지불 의사는 미검증입니다. 현재 수치는 서버 실행시간이며 사람의 절약시간이 아닙니다.

**개발 기간과 AI 활용은 어떻게 공개하나요?**

9월26일 시작한 원형을 재사용했고 대회 기간에 비동기 복구, 디지털 검토, 개정 후 새 검사와 현재 목표 보호를 추가했습니다. Codex를 코드·테스트·분석·자료 제작에 광범위하게 사용했습니다. 이번 제출 준비의 하위 에이전트 3개는 AI 자료 제작·검수이며 사용자 참여가 아닙니다.

**왜 실제 사용자나 실물이 없나요?**

이번 범위는 기존 하드웨어로 끝까지 돌아가는 디지털 자료 검토입니다. 실제 사용자 0명·실물 완료 0건을 공개하고 현재 머신 실행 증거로 구현을 설명합니다. 사람의 효율과 현장 신뢰성은 후속 독립 검증 항목입니다.

## 팀원 리허설 확인

1. 6분 타이머로 한 번 읽고 실제 대기 동안 설명할 부분을 확인합니다.
2. 공개 영상 3→2와 별도 대조 2→3을 혼동하지 않습니다. “사진을 보충했다”라고 말하지 않습니다.
3. 수치는 51장 41/3/7, 같은 도메인의 별도 24장 23/0/1, 기계 흐름 5/5·검사 4회로 구분합니다.
4. “정확도 100%”, “현장 오류 0”, “사람 효율 향상”, “세계 최초”, “경쟁 제품보다 우수”로 바꾸어 말하지 않습니다.
5. 제출 전 본인의 팀 정보와 공식 신고 항목을 실제 정보로 확인합니다.
