# 无自采照片时的开发路线

核查日期：2026-09-26。用户目前没有自采照片，继续使用来源明确、许可适用的公开实拍数据推进开发。自采照片不是程序开发的前置条件，也不需要工厂或车间场地。

本文件记录已核查的数据源及下一阶段方案。尚未下载下列数据集、提交网站下载表单或取得实物计数评测结果。

## 优先数据源

### MVTec LOCO AD：screw_bag

- [官方页面与许可证](https://www.mvtec.com/research-teaching/datasets/mvtec-loco-ad)
- [作者论文](https://link.springer.com/content/pdf/10.1007/s11263-022-01578-9.pdf)，第3节、表1。
- 实拍零件袋与正常/异常样本适合检查零件数量和组合；数据提供异常区域掩码，并非完整的逐件计数表，需要补充复核计数标签。
- 论文中的正常袋含两垫圈、两螺母、一长螺丝、一短螺丝。当前程序将螺纹件归于bolt，不能发现“长螺丝替代短螺丝”这类总数量不变的错配。首轮只评估预先定义、适合当前分类的数量案例，单列不覆盖的长短规格和结构缺陷；不报告整个LOCO异常检测任务的准确率。
- 本次核查时官方下载需要填写表单。没有代用户提交姓名、联系方式或其他身份信息。

### MVTec Screws

- [官方页面与许可证](https://www.mvtec.com/research-teaching/datasets/mvtec-screws)
- 官方描述为384张照片、13种螺丝/螺母类别、4,426个带方向的边界框标注。适合零件辨别及部分计数评估。
- 类别映射须先定义。不能把所有螺丝类型未经说明合并为某个规格的螺栓，也不能声称此数据覆盖垫圈、角码和完整补件流程。

两套官方数据均为CC BY-NC-SA 4.0，包含署名、非商业和衍生材料同方式共享条件。保留原许可和引用；不因“学生比赛”就假设全部展示、再分发及后续商业用途均获准。参赛使用方式应与比赛条款及数据许可核对。

## 实施顺序

1. 获取许可适用的数据后保存来源URL、下载日期、许可证、原始文件哈希和原有数据划分。原始图不覆盖。
2. 先检查类别与画面是否适配KitGuard；数量真值独立核对，不以模型回答作为答案。超范围或无法明确计数的图片标明原因，不在看到模型结果后选择性删除。
3. 使用开发子集调试提示和输入规范。保留独立测试子集，同一原图及其裁剪/增强版本不能跨开发与测试集合。
4. 实际运行本地模型，保存逐张结果、计数差异、错误放行、拒绝/人工处理及用时。公开数据的成绩只描述该测试集，不代替用户现场表现。
5. 建立标明“公开数据回放”的演示案例，说明照片来源、原始标签和订单规则。订单修改、旧检查失效、人工确认等软件行为可继续独立测试。

## 能验证什么

公开实拍图可以验证静态识别、数量对照、缺件判断、遮挡时拒绝和模型耗时。当前KitGuard已经支持上传本地图片，因此公开数据下载后可以通过同一真实推理路径使用，无需等相机或自采照片。

单张静态图通常没有同一现场“移动零件、补件、复拍”的连续证据。任意两张不同照片不能充当一次真实操作的前后对照；数字合成或AI生成的场景应标为模拟测试。它们可验证交互流程，但不能作为真实补件成功率、现场节省时间或用户实验结果。

后续若条件允许，用手机在普通桌面拍摄少量零件即可补充真实闭环验证，无需取得工厂访问权限。若始终没有自采条件，交付范围保持为“公开数据静态评估＋明确标注的流程回放”，并如实说明尚未验证的环节。
