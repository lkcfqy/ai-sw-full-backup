# KitGuard v0.3 현장 시연 안내

이 문서는 해피 팀의 내부 리허설용이다. 공개 사진 시연과 실제 부품 작업을 구분한다. 최신 모델 선택과 수치는 같은 폴더의 `FINAL_EVALUATION.md` 및 동결 평가 기록을 따른다.

## 시작 전

1. Mac을 전원에 연결한다. 다른 로컬 모델 추론과 벤치마크가 실행 중이면 동시에 시작하지 않는다.
2. 프로젝트의 `启动KitGuard.command`를 실행하거나 프로젝트 폴더에서 `bash scripts/run.sh`를 실행한다.
3. 브라우저에서 `http://127.0.0.1:8765`를 연다. 모델 파일 존재와 실제 메모리 로드는 다른 상태다. 최초 검사는 로딩 시간을 포함할 수 있다.
4. 사전 점검은 `.venv/bin/python scripts/preflight.py --help`로 지원 옵션을 확인한 뒤 실행한다. 사전 점검 성공은 모델 정확도나 카메라 실물을 검증했다는 뜻이 아니다.

## 공개 사진으로 설명할 때

`http://127.0.0.1:8765/static/demo.html`에는 출처와 SHA가 고정된 개발 사례 3개가 있다. 원하는 사례로 새 주문을 만들면 공개 이미지 표지가 계속 유지된다. 생성만으로 모델이 실행되지 않으며, 검사 버튼을 눌러야 실제 로컬 추론을 한다. 공개 사진 주문은 실물 완료를 기록할 수 없다.

권장 설명 순서:

1. **필요 수량과 관찰을 분리한다.** 주문의 목표 수량은 화면과 규칙 엔진이 보유한다. 시각 모델에는 목표 수량을 보내지 않는다.
2. **현재 사진을 실제 검사한다.** 처리 중 상태와 실제 대기 시간을 보여 준다. 준비된 정답이나 이전 검사 결과를 새 검사처럼 보여 주지 않는다.
3. **수량만 보지 않고 근거를 연다.** 물체 번호는 모델이 추정한 위치다. 강화 프로토콜을 사용한 검사라면 두 방향 결과와 국소 신원·구멍 형태 판단도 보인다. 같은 모델의 반복 호출이므로 독립 전문가의 합의라고 설명하지 않는다.
4. **주문을 수정해 새 버전을 만든다.** 기존 검사가 더 이상 유효하지 않은 것을 보여 준다. 과거 사진 기록을 새 버전의 현재 증거처럼 재사용할 수 없다.
5. **현재 버전에 사진을 다시 제출하고 재검사한다.** 같은 공개 사진을 다시 올렸다면 “동일 공개 사진 재업로드로 버전 제약을 확인했다”고 말한다. 부품을 보충하거나 실제 장면을 바꿨다고 말하지 않는다.
6. **증거 ZIP을 내려받는다.** 압축을 풀고 `OPEN_ME.html`에서 해당 주문의 과거 검사와 사진, 수량 차이, 해시를 확인한다. 네트워크 없이 읽을 수 있지만 SHA만으로 현장 진위를 증명하지는 못한다.

실제 결과가 불확실이면 그 상태를 그대로 보여 준다. 결과를 얻을 때까지 반복해 가장 좋은 한 번만 남기지 않는다. 고정 개발 사례의 시연 성공은 새 테스트셋 정확도가 아니다.

## 실제 부품을 촬영할 때

일반 새 주문을 만든 뒤 실제 부품을 겹치지 않게 배치한다. 사진 촬영 → 미리 보기 → 필요 시 재촬영 → 저장 순서로 진행한다. 브라우저가 카메라 권한을 거절하면 파일 업로드를 사용할 수 있다. 카메라가 연결되지 않았는데 연결되었다고 가정하지 않는다.

보충·제거 지시가 나오면 사람이 실물을 조정하고 새 사진을 제출해야 한다. 수량이 맞아도 작업자가 실물을 확인한 후 직접 완료를 기록한다. 시연 준비 없이 누르기만 해 물리적 완료를 만드는 절차는 없다. 동일 사진 내용은 새 ID나 파일 메타데이터만 바뀌어도 추가 증거로 세지 않는다.

## 발표 문장

> KitGuard는 수량을 한 번 답하는 챗봇이 아니라, 현재 주문 버전과 사진 증거를 연결하는 작업 도구입니다. 모델은 보이는 부품을 관찰하고, 프로그램은 수량과 버전을 검증합니다. 증거가 부족하면 재촬영이나 사람 확인을 요구하며, 과거 결과로 새 주문을 완료할 수 없습니다.

추가 질문에는 `JUDGES_QA_KO.md`의 짧은 답변과 최신 원시 기록을 함께 사용한다. 효과는 실제 평가 범위 안에서만 설명한다.

## 문제가 생겼을 때

| 증상 | 확인과 대응 |
| --- | --- |
| 포트가 이미 사용 중 | 먼저 기존 `127.0.0.1:8765` 화면을 확인한다. 별도 GPU 서버를 중복 실행하지 않는다. |
| 모델 파일은 있으나 아직 로드되지 않음 | 정상적인 지연 로드 상태일 수 있다. 첫 실제 검사에서 로드된다. |
| 검사가 느리거나 응답 상한 초과 | 실제 상태와 시간을 공개한다. 타임아웃 후 GPU 작업이 계속될 수 있으므로 연속 클릭하지 않는다. 필요 시 본인이 시작한 서버 창에서 종료 후 다시 시작한다. |
| 주문 수정 후 검사 불가 | 현재 버전에 사진을 다시 제출한다. 이전 버전 사진 기록으로 완료를 우회하지 않는다. |
| 공개 사진 주문의 완료 버튼 없음 | 의도된 동작이다. 공개 사진은 실물 작업 완료의 증거가 아니다. |
| 인터넷이 끊김 | 설치된 로컬 모델과 작업대는 로컬에서 실행한다. 원본 다운로드와 최초 설치는 별개다. 기존 증거 ZIP과 전체 대기 시간을 보존한 녹화는 읽기 전용으로 볼 수 있다. |

저장된 녹화를 보여 줄 때는 녹화임을 먼저 밝힌다. 라이브 모델과 혼동시키지 않는다. 실제 현장 실험 계획은 `../REAL_WORLD_VALIDATION.md`에 별도로 보존한다.
