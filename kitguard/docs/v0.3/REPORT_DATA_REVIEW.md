## 已发现并复核修复的问题

1. **完成记录约束不足。** 旧刷新逻辑主要相信 `completed` 标志，探测器尤其缺少完整性核对。现检查完成时间、计划 ID 唯一且与预测顺序一致、完成计数、模型源码前后哈希及保留快照、回放输入未变；探测器检查脚本未变、总与各 cohort 的计划/完成/精确计数分母，并从逐例数据重算数量、错误与中位数。
2. **来源流程描述错配。** 功能工程证据与候选选择曾共用模型运行来源文案。现分别描述浏览器工程记录、去重测试、开发协议及选择状态文件，不把 UI 夹具当作识别成绩。
3. **耗时定义不适用于回放。** 历史表总定义已补上回放是“历史基础 + 新调用”；行级说明继续区分上传/observe、回放及 CPU 探测器。
4. **失败刷新可能写入半成品。** 历史刷新现支持 `write=False` 返回内存快照，v0.3 全部验证成功后才写文件。异常夹具均验证目标文件字节未变。
5. **开发状态文字短暂落后。** 集成完成后已更新 `REPORT_SELECTION_STATE.json`；目前准确区分完整开发已完成与新留出运行中，并说明基准是同次首轮、不是独立专家或现场试验。
