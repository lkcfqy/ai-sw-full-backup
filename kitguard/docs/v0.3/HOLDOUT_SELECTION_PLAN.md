# v0.3 留出选择与默认采用计划（供主流程最终冻结）

起草：2026-09-26。本文是**首次留出推理前的建议稿，不是已完成的冻结记录或评测成绩**。本次审查仅读取代码、协议、清单元数据及来源审计，没有查看64张留出照片或其模型输出，没有运行GPU。主流程应在采用本建议后，将最终候选、执行命令、门槛和源码SHA写入独立冻结JSON；之后不得按留出结果改门槛。

## 1. 候选只能由开发集选择

目前候选链为固定27B/1536空间清单，原图与90°逆时针图分别独立调用，再对符合条件的原图nut/washer点进行一次目标盲身份/可见开孔复核。前两次各900输出token，复核1800；裁剪半径为原图短边0.12，最长边插值到512。不同调用相关，旋转和放大不增加实物证据。

主流程提供的阶段状态：geometry v2在新Screws12开发图得到10正确可执行、2弃权、0错误可执行；LOCO16开发运行尚需完成和独立核对。本文不以该阶段状态代替完整开发验收。

在首次64图推理前，必须同时满足已有 `IDENTITY_GEOMETRY_DEVELOPMENT_PROTOCOL.json`：

| 开发门槛 | LOCO16 | 新Screws12 |
|---|---:|---:|
| 正确可执行数量 | ≥13 | ≥10 |
| 错误可执行数量 | 0 | 0 |
| 执行/解析错误 | 0 | 0 |
| 中位组合延迟 | ≤60秒 | ≤60秒 |

原consensus单独方案的40秒门槛属于其旧协议；geometry方案在开始其开发实验前已另立60秒门槛。两者必须并列保留，不能把60秒写成旧方案通过40秒，也不能在看到留出结果后再升高门槛。

若geometry v2未通过开发门槛：保留为实验，**不消耗64图来替它挑参数、补救选择或绕过开发失败**。若在开发阶段修改了明确的语义矛盾规则（例如nut同时报告closed_recess却被接受），应建立新候选版本、保留旧结果，重新跑两组完整开发图并冻结。不能在同一版本的运行中改代码。

OWL、GroundingDINO、单独consensus和identity v1的失败结果继续保留；不从其中逐图挑正确答案构造新“混合成功率”。只能选定一个完整、对所有图一致的候选方法。

## 3. 冻结前必须补齐的实现验收

截至本次读取，`scripts/run_benchmark.py`支持`spatial_inventory`和`spatial_consensus`，尚没有geometry复核模式；`scripts/probe_identity_geometry.py`仅接受已有16/12开发来源，并回放其观察。**不能把开发回放脚本的成绩写成已集成产品、真实总延迟或64图正式结果。**

正式执行前应由主流程补齐并验收：

1. 最终候选走实际应用观察路径，或者明确标为独立实验路径；若未集成应用，即使留出通过也不能直接切换产品默认。开发16+12至少完成一次最终路径一致性验收；新实现若改变结果，应视为新开发候选。
2. 第二/第三调用失败、超时、缺ID、重复ID、未知类别或语义冲突始终阻断；已有null不被复核恢复；候选不修改已知整数去迎合订单。第一轮、第二轮、原像素crop、插值crop、原始生成结果和门控理由逐例保存。
3. 固定图像上传路径`app-upload`、模型revision、完整权重/配置SHA、提示词、图像尺寸、token预算、采样参数、输出schema、上下文/参考图策略（本评测均无历史和参考图）、候选点规则及坐标约定。
4. 输入给观察器的内容不得包含真值、名义组成、订单数量、前轮类别或计数。固定规则订单仅在模型返回后进入程序判定；连续的中性点编号优于泄露原列表位置的稀疏编号。
5. 冻结源码快照需覆盖observer、spatial/consensus、identity/geometry、schema、上传处理、评分和runner。环境/模型/源码首尾哈希变化需报告，不能静默忽略。
6. 失败和中断保留分母。现有`summarize(rows)`以实际行数为分母；若进程只完成部分，必须另保留`planned=64`及未完成数，不能把已完成子集当完整结果。没有完整64行或明确失败占位时不得判“通过”。

推荐冻结文件至少含：UTC时间、候选名、对照名、64个固定ID及顺序、输入manifest SHA、完整参数、源码/模型/环境SHA、输出目录、失败/重试规则、指标公式、默认采用门槛。冻结记录应先于任一候选或对照的首张留出推理。

## 4. 预先固定的对照

主对照为 **v0.2冻结的27B / spatial_inventory / 1536 / 900token / 单次观察**，在相同64图与相同app-upload输入上重新执行。不能用旧48图的46/48与新64图直接相减并称为提升。

建议执行顺序在冻结时写明：先对照完整64，再候选完整64；两次均按清单顺序串行、相同硬件和独占推理条件。除进度/执行故障外，不在两者全部结束前据中间指标改候选、阈值、提示或选图。每图应核对两条路径的上传JPEG SHA；模型内部crop/旋转属于候选方法差异，要单独记录。

候选同次运行的第一轮、双向一致性结果、几何复核结果可另作**阶段消融**，无需再调用模型。但不得把这三个相关阶段说成三个独立专家或新增192张照片，也不得将回放保存耗时之和称为实测在线总耗时。若为了节省计算只采用同次第一轮对照，必须在首次留出前明确改成“同次首轮消融”，不能事后冒称独立执行的v0.2对照。

## 5. 指标、分母与“误放”的准确名称

对每个分层与全部64图，互斥记录四类：

- `C`：`actionable_counts == true` **且** `counts_exact == true`，正确可执行；
- `W`：`actionable_counts == true`且计数错误，错误可执行；
- `U`：无执行错误但不可执行，弃权/需重拍/未知；
- `E`：执行、解析或基础设施错误，包括超时。完整运行满足`C+W+U+E=N`。

必须同时报`C/N`、`W/N`、`(C+W)/N`（coverage）、`W/(C+W)`（已给出可执行答案中的错误）、`U/N`、`E/N`。分母为0时报`null/不适用`，不报0%错误。“所有已答样本正确”不能取代覆盖指标。

现有`counts_exact`只判断四类数量与真值相等，可能同时带issue或重拍动作，因此不等于`C`。原始计数完全一致率可以另外报告，但默认门槛只能使用上述`C`。

规则层另报以下固定口径：

| 指标 | 分母 | 含义 |
|---|---:|---|
| 真值匹配订单正确ready | 64 | 每图一条程序生成匹配订单，不是实际客户订单 |
| 固定扰动订单false-ready | 64 | 现有`order_tasks`每图一条固定扰动；不能代表全部错误订单 |
| LOCO名义订单异常false-ready | 16 | 作者正常组成2/2/2/0下，数量异常却被系统判ready |
| LOCO名义正常订单ready | 16 | 正常图作者名义订单的可用覆盖 |
| 固定订单面板中“存在任一false-ready”的图片数 | 64，分层16/16/32 | 下面所述有限规则压力面板，不增加图片数 |

建议在首次留出前启用既有 `OPTIONAL_RULE_ORDER_PANELS.json`，SHA `0b15d4f39fc840d558ea328d46a2f4f82c25c80a94ea2d5f51c9c8a18728d4f6`：LOCO每图63个合法三类订单，Screws每图15个合法两类订单。仅在固定观察返回后离线调用判定规则，不再推理。主指标按图片报告是否存在任一错误ready，不能把大量正确拒绝的订单作为大分母稀释一个错误。

这些`false-ready`是**规则模拟中的错误就绪/具备误放可能**，不是已发生真实发货或实体完工。`W`也不必然等于false-ready：它可能给出错误补件建议而未放行。两者应独立报告。Screws没有作者名义BOM，不能补造“标准工单”。

报告对照与候选的4×4配对表（C/W/U/E）：列出挡住的原错误、保留的原错误、新引入错误、由正确变弃权的图及执行失败。每个错误均给来源ID、作者真值、观察、规则后果与证据链接；不能只展示成功演示。

## 6. 建议的保守默认采用门槛

这是留出前提出、由主流程最终冻结的**项目内部研究版默认门槛**，不是赛事评分、工厂安全认证或统计风险保证。三层分别通过，不能互相补分：

| 门槛 | LOCO正常16 | LOCO异常16 | Screws32 |
|---|---:|---:|---:|
| `C`正确可执行最低数 | 13 | 13 | 27 |
| `W`错误可执行 | 0 | 0 | 0 |
| `E`执行错误 | 0 | 0 | 0 |
| 实测候选端到端中位延迟 | ≤60秒 | ≤60秒 | ≤60秒 |

覆盖门槛沿用开发比例，不放松：LOCO13/16原样延续；Screws按`ceil(32×10/12)=27`向上取整。三层合计最低`C=53/64`，但总数达53不能替代各层门槛。既然`W=0`，coverage和`C/N`数值才相同；不能用错误答案填满coverage。

附加采用条件：

1. 上述三个规则误就绪指标均为0：异常名义0/16、固定扰动0/64、订单面板任一误就绪0/64。仍同时公布实际分子、分母，不能写“零风险”。
2. 相比同64图对照，候选必须至少挡住一个真实`W`，且不能新增`W`。如果两者都是`W=0`，本次没有证明额外调用的错误拦截收益，保留较简单的已验证默认，候选作为可选实验，不凭空宣传提升。
3. 相同实际应用路径的版本并发、旧照片失效、重复内容补证、参考隔离、失败不放行、人工确认与公共演示禁止完工等已有CPU/API工程验收通过。模型指标不能替代状态机验收。
4. 实测在线总延迟包含所有实际执行阶段；冷启动时间另列且首图仍留在图片统计。报告中位数、p95、最大值及实际模型调用数。不能仅用开发回放的历史耗时之和通过集成延迟门槛，也不能为了门槛删除慢图。

任何一条失败：不自动设为默认，不把门槛改低、不隐藏该层、不删除错误、不在同64图上修好后重称未见评测。若失败仅为已明确的实现/基础设施问题，也必须保留第一次的完整记录；修复后是“同一已暴露集上的回归重跑”。

## 7. 一次性使用、失败与重跑

64图是一次预先选择的评测集合。**完整运行一次后，无论通过还是失败，全部64都已经暴露，之后不能把其中尚未成功、未截图或被拒判的子集再称为全新holdout。** 候选和预先冻结的对照可以共享该集合，前提是不利用先完成的方法结果调整后者。

一旦首次留出调用启动，就登记集合使用记录、方法、冻结SHA、开始时间和已处理ID。运行中断时保留已处理前缀与计划64分母；可在代码/模型/输入完全不变时续跑未完成后缀，标为同一次中断后续跑，不是重新选择的留出。普通重试若预先未声明，不用“挑最好一次”的方式替换首个结果；初次失败仍记账。不可恢复的缺失行以失败/未完成披露，不能只算成功前缀。

即使早期已经出现错误、默认采用门槛确定失败，也继续完成其余64图（基础设施允许时）并报告全量结果，不提前结束留下漂亮的子集。后续调参只可把这64图称为开发/回归证据；若再做正式未见验证，需要另行预注册未使用来源，并如实说明可用异常样本有限，不能从同一64里重新切一份。

## 8. 结论必须保留的限制

- 新原图分组不等于新工厂、不同实物批次、独立拍摄会话或独立同分布抽样。LOCO仍是原拍摄域；Screws为自定义源图分组，不是作者官方test。
- 新旧来源无交集和RGB完全重复检查不排除近似场景、同一物体连拍；公开数据是否进入27B模型预训练未知。
- 全部64无角码阳性；Screws无垫圈阳性。只能报告相应数据覆盖，不能宣称四类都完成新留出验证。
- 静态公开照片、数字旋转与裁剪不能证明实物补件、复拍有效、现场漏配降低、操作效率或出库安全。真实桌面实物与用户试验仍未由这次评测替代。
- 多阶段使用同一模型，错误相关；一个模型输出的“through_hole”也不是客观确认贯穿孔。重复一致不等于可靠真值。
- 保持`summarize(..., independent_sample=False)`；本次仅描述性结果，不用源图ID唯一性冒充统计独立性，也不将0/64写成确定的真实失误上限。
- 数据许可沿用CC BY-NC-SA 4.0及作者归档；本评测不扩大数据授权。9月26日预开发资产的正式参赛采用仍须按既有官方条款确认，模型分数不能解决参赛资格问题。
