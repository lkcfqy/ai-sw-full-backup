# 전체 과제 사용자 시험 / 完整任务用户试用

**这是执行工具和预定协议，不是已有真实用户结果。/ 실행 도구와 계획이며 실제 사용자 결과가 아닙니다.**

入口：`http://127.0.0.1:8765/static/trials.html`。当前只监听本机：主持人和参与者使用同一台 Mac 的不同浏览器或隐私窗口，交接时关闭/隐藏主持人真值页面；手机不能直接访问这条本机地址。手机照片用 AirDrop/数据线传到 Mac，再在计时内上传。独立于旧 `/static/study.html` 固定照片工具；两种协议、用时和分母不能合并。无需 GPU 即可准备与执行人工/规则任务；KitGuard 使用主工作台的真实本地模型。测试替身与独立两类 detector 实验输出不能代替主工单的模型证据。

真实试用选择 `source_kind=self_reported_physical`。开发界面测试选择 `engineering_fixture`，实物与真人同意声明保持 false，不与真实批次混算；两者都固定记录 `physical_verified=false`、`participant_identity_verified=false`，因为软件不认证实物或人员。工程模式也不放宽 KitGuard 完成的真实模型校验。

## 1. 人与物 / 사람과 물체

需要 3 名自愿参与者和 **1 名不担任参与者的主持人**。界面只保存稳定匿名代号，不填姓名；`host` 是保留角色名，不能作为参与者代号。参与者来源、同意与主持人身份是人员声明，软件不认证。若只有两名队员，可由一名做主持人，另一名连同另外两名自愿者做参与者；如需外部用户反馈的赛事证明，另按主办方要求保留实际证明，不把本工具的匿名代号当身份证明。

3명의 자발적 참여자와 **참여하지 않는 진행자 1명**이 필요합니다. 이름 대신 익명 코드를 사용합니다. 코드·동의·출처는 진술이며 독립 인증이 아닙니다. 대회 피드백 증빙은 주최 측 요건에 따라 별도로 준비합니다.

实物：外观可区分的螺栓、螺母、垫圈、角码，每类准备至少 2 件，以及备用补件。纸画编号格或托盘、相同照明、同一手机/相机和电脑。四类都必须有真实物件；缺类时先补齐材料，不把网络图、生成图或未知数填 0。主持人负责逐件清点、摆放、保管实物和最后复核；用户操作不能由模型代写。

실제 볼트·너트·와셔·브래킷 각 2개 이상과 여분, 번호 칸/트레이, 같은 조명·촬영 장비가 필요합니다. 없는 종류를 공개 사진이나 0으로 대신하지 않습니다. 진행자가 실물을 직접 배치·계수하고 최종 상태를 확인합니다.

## 2. 固定规模、分配与比较条件 / 규모·배정·비교 조건

创建前选择其一，不能看到结果后换规模或删任务：

| 规模 / 규모 | 分配 / 배정 | 解释 / 해석 |
|---|---|---|
| `pilot9` | 3 人 × 每人 3 任务；每人三种方法、三种场景各一次；总体 9 个 method×scenario 配对各一次 | 最小探索试点，方法与任务变体不能完全分离 |
| `study27` | 3 人 × 每人 9 任务；每位参与者覆盖全部 9 个 method×scenario 配对 | 完整交叉的探索试用；仍然只有 3 位参与者 |

三种方法：人工清单、编号托盘＋规则、KitGuard。场景：正常、首次检查后变更订单、纠正缺件。顺序由系统用固定拉丁方公式生成，冻结后不能挑选或重排。不同任务使用匹配数量与一次增减的变体，并由主持人重新摆放；不能把同一照片复制成新任务。冻结保存分配、协议、记录器、模型身份和已知公共来源清单哈希。

수동·규칙·KitGuard와 정상·주문 변경·누락 수정 과제를 고정 순서로 배정합니다. 같은 사진을 반복해 새 과제로 만들지 않습니다. 동결 후 배정·규모를 바꾸지 않습니다.

人工和规则模式都使用同样的实际托盘、正确 BOM、可获得的参考物；规则由人输入亲自清点的数量，软件计算差额。人工模式只记录计数，不自动计算差额。**不强迫基线拍摄不需要的照片**：实际方法不需要的步骤不应人为增加。KitGuard 的拍照、上传、参考图登记、等待和复拍均在计时内；不能提前准备该任务照片或偷偷在另一工单看模型结果。共同场地布置及所有参与者接受的相同使用说明在计时前完成，不属于逐任务时间。若做统一练习，使用独立未入组布局、记录练习方式，不拿正式任务练习。

수동·규칙에 불필요한 촬영을 강제하지 않습니다. KitGuard에 필요한 촬영·참고사진 등록·업로드·추론 대기·재촬영은 시간에 포함됩니다. 공통 환경 준비·동일한 사용 설명은 과제 시작 전이며 별도 범위입니다.

订单变更阶段给所有方法相同的结构化新 BOM。KitGuard 要在主工单批准变更；规则/人工按已揭示目标继续。**这不测自然语言改版准备成本**，不能据此声称语言 Agent 的效率优势。相同人的学习、不同变体和仅 3 人使两种规模都只能做描述性探索，不能宣称因果提效、统计显著或工业可靠性。

## 3. 最少人工操作 / 최소 수동 절차

1. **主持人创建、保存入口、冻结。** 填 3 个参与者代号、不同主持人代号、session、实物来源声明，亲自勾选自愿同意和实物确认。立即私下保存页面生成的入口文件。主持人链接能看到布置/真值，不能交给参与者；每位参与者只拿自己的链接，使用这台 Mac 上的独立浏览器环境。浏览器 `localStorage` 仅保存由高随机主持人令牌派生密钥加密的入口列表，持原主持人链接刷新即可解密恢复；明文主持人令牌不保存在该列表中。浏览器存储不可用时会明确提示立即下载文件。主持人链接/令牌和私存文件全丢失后，系统不补发密钥；不能从无权限 API 取回，不另造“恢复认证”。
2. **逐任务布置并清点两遍。** 主持人按该任务“初始实物布置”实际摆放，第一次输入后隐藏输入，再重新逐件清点第二次。两次与预定布置一致才能锁定。数量不一致就实际检查、调整，不看模型来裁决。可在分配冻结后逐个准备，不要求同时摆放 9/27 盘。锁定后保持实物不动；错误锁定的任务留为未开始并披露原因，不偷偷改真值。
3. **参与者开始后才揭示订单。** 本人确认同意、未提前看答案，点击开始。服务器此时开始计时；之后拍照、上传、调整、推理等待、补拍、输入和求助都计入，没有暂停按钮。界面秒表仅近似显示，导出使用服务器单调时钟。
4. **按分配方法做真实任务。** 人工/规则亲自清点并输入。KitGuard 点击“打开实际工单”，只操作自动创建的这个主工单，上传实拍照片及需要的参考图，运行真实核验，按结果实际移动/补件/复拍。没有模型或不能完成就如实失败；不能用 demo、测试结果、其他工单或预先预测 JSON 替代。动作备注明确是参与者声明，工单事件才是服务器观察到的软件操作。
5. **订单变更场景：** 先记录初始计数（KitGuard 先得到一次实际检查，暂不确认完成或记录人工终结），再点“揭示变更”。KitGuard 在主工作台修改工单，批准显示的新 BOM 为 R2，并按最新版本重新拍摄核验，最后才确认完成。不要额外点“开启新版本重新处理”；试验要求恰好一次改版。其他方法按新目标继续检查和实物调整。不能提前跳过变更。
6. **参与者提交即停表。** 选“认为已完成 / 失败 / 放弃”，如有他人接管判断必须勾选，失败/放弃填写真实原因。KitGuard 的完成须有主工单当前版本的有效检查、真实模型身份与完成回执；无法达成选失败。请求仍在运行时等待它结束后提交，以保留返回结果。提交后不再移动实物。
7. **主持人独立终态核对。** 使用主持人入口点开始复核，直接清点提交后未改变的实物两次；不抄参与者或模型的数量。复核时间另列，不加回参与者用时。主持人必须与参与者不同代号；相同代号或两遍不一致不能提交。接管和独立角色真实性仍由人保证。
8. **全部执行或明确停止后关闭、导出。** 未开始、未复核、失败、放弃和重启中断都留在预定分母。关闭后不可重开、补做、覆盖结果。保存导出 JSON 及本地原照片文件/数据目录。主持人复核未完成也能关闭，但只能显示待复核，不能算正确。需要纠正协议或真值时保留原批、新建明确修订的批次并说明是否已经看过输出。

진행자가 생성·링크 보관·동결 → 과제별 실물 두 번 계수 → 참여자가 시작 후 주문 확인 → 지정 방법으로 실제 작업 → 제출 즉시 계시 종료 → 별도 진행자가 최종 실물을 두 번 검수 → 미시작·실패 포함 전체 배치 닫기·내보내기. 진행자 링크는 참여자에게 주지 않습니다. 제출 뒤 물체를 옮기면 “변경 없음”을 확인할 수 없으므로 검수를 완료로 기록하지 않습니다.

## 4. 결과를 읽는 법 / 결과 해석

各方法固定计划分母：`correct + wrong + unreviewed + failed + abandoned + interrupted + not_started = planned`。`correct` 指参与者申报完成且主持人终态与目标一致；不等于 AI 自主成功。`takeovers` 单列，不能把他人接管解释成系统独立完成。完整模型输出在提交快照中保留，失败不能抹掉此前返回的错误。

`takeovers` 当前只统计“由他人接管判断”勾选；参与者本人接手 AI 时，在原因中明确记录。KitGuard 需要人工代替 AI 判断而无法达成完成条件时，回试用页选失败、说明接手方式并提交停表；主工单的人工复核不会自动停表。按软件提示补件、移动、复拍属于正常任务动作，不自动算接管。주문 변경 과제에서는 첫 검사 뒤 완료하지 말고 변경을 공개한 다음 R2로 한 번 수정하고 재촬영·검사 후 완료하세요. 사람이 AI 판단을 대신해야 했다면 실패 사유에 기록하고 과제 페이지에서 제출하여 계시를 끝냅니다. 현재 인계 집계는 다른 사람의 판단 대행 체크만 포함하며, 본인의 AI 대행은 비고에 기록합니다.

终止任务、申报完成任务、复核正确任务分别给出时间的 `n/median/max`；不只报告成功者时间，更不能把未开始的空值当作 0。服务器重启：正在执行的任务为 `interrupted`、耗时 `null`，保留已有动作和工单记录；已提交任务仍可复核，跨重启的审核耗时为未知。旧计时器不能重启续造连续时间。

각 방법의 예정 분모를 유지합니다. 완료·정답·실패·미검수·미시작을 구분하고 시간마다 n을 표시합니다. 도움을 받은 성공은 자율 성공이 아닙니다. 서버 재시작 시 실행 중 과제는 중단·시간 미상으로 남습니다.

公开来源保护读取 Screws、LOCO、InO、已登记裁剪及公共 demo 的 manifest 原图哈希，并关联本地工单的原始/规范化来源关系。导出 `public_source_coverage` 列出逐清单记录数、缺失和覆盖范围；本模块不全量解码公共图片，所以 `normalized_pixel_records=0`，不能声称阻止所有近似图片。公共来源缺失会明确列缺口；已知公共图、其他工单同来源图和测试 backend 不能通过 KitGuard 完成校验。失败记录仍保留原始不合格输出，但 `ai_completion_evidence_validated=false`，不宣称真实 AI 完成。

工单照片与快照导出时检查文件哈希；哈希不是人员、原始拍摄时间、实物或独立盲法认证。这个本地应用不提供恶意管理员防篡改或人员身份验证。不要公开入口令牌文件。

## 5. API integration / 接口

初始化 `TaskTrials(store, engine.status)`，在 `store.recover_interrupted()` 后调用 `task_trials.recover_interrupted()`，挂载 `task_trial_router(task_trials)`。独立 SQLite 表 `task_trial_batches`，旧 `field_studies` 不变。

`POST /api/task-trials` 创建，返回一次性展示的主持人及参与者入口令牌。其余请求使用 `X-Trial-Token`，不放 URL query。页面使用 URL fragment。`GET /{id}` 依角色隐藏未开始 BOM 和真值；主持人 `freeze / tasks/{task}/setup / review-start / review / close / export`；参与者 `tasks/{task}/start / observe / reveal-change / actions / submit`。API 完整前缀为 `/api/task-trials`，严格拒绝额外字段、布尔计数和假确认。

验证命令：`.venv/bin/python -m pytest tests/test_task_trials.py -q`。测试只使用合成图片、代号和假时钟，**不是实际用户或模型准确率证据**。
