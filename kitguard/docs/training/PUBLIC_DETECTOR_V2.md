# Public Detector v2：仅提高输入分辨率的固定实验

协议固定时间：2026-09-30 04:09:46（韩国时间，UTC+09:00）。

状态：已完成固定12轮训练、验证复算，以及冻结模型后由根代理执行的一次旧22图回归。回归中的完整计数结果退步，**v2不晋升为默认模型，实验台继续默认使用v1**。实验目录为 `training-runs/public_detector_v2_mps_960_20260930/`。

## 问题与选择依据

本轮检查公开 bolt/nut 检测器提高输入分辨率后，是否能改善每图两类数量同时完全正确率。只使用原 v1 的训练集、验证集、协议及训练历史作训练配置和模型选择决定。原22图 test 已在 v1 阶段曝光，训练及选模阶段不读取其标签或预测、不运行该集、不用其结果调参；训练器对 test.json 的既有哈希读取仅作数据完整性检查。模型和阈值冻结后的回归单独记录在下文。

v1 使用214张训练图、44张验证图，均为1920×1440。12轮训练的最佳验证结果为第10轮、阈值0.5：38/44图数量完全正确，F1为0.978644；总训练和逐轮验证耗时313.33秒。第11、12轮的主指标未继续提升。因此，本次保持12轮预算，优先只改变输入大小；不同时延长训练轮数或修改anchors。

由训练标注按实际缩放比例复算，v1短边640时，777个nut中197个框短边小于32像素；短边960时仅1个。验证集156个nut中，短边小于32像素的数量由43变为0。这里的32像素仅作尺寸诊断，不是模型可检出与否的界限。高分辨率是否改善识别仍需训练结果验证。

Torchvision按短边缩放并用长边上限约束；对本数据，v1约为853×640，v2为1280×960，线性尺寸增至1.5倍、像素数约为2.25倍。[官方实现说明](https://docs.pytorch.org/vision/stable/_modules/torchvision/models/detection/faster_rcnn.html)

## 固定协议

| 项目 | 固定值 |
|---|---|
| 模型 | `fasterrcnn_mobilenet_v3_large_320_fpn`，COCO_V1权重重新初始化 |

| 唯一训练配置变化 | `min_size=960, max_size=1280` |

| 设备与精度 | MPS、FP32，6个CPU线程，MPS fallback关闭 |
| 优化器 | SGD，lr=0.005、momentum=0.9、weight_decay=0.0005 |
| 学习率 | 前100步warmup；StepLR每8轮乘0.1 |
| 数据 | 原固定214 train / 44 val；不重新拆分 |
| 增强 | 仅train，水平/垂直翻转各独立p=0.5 |
| anchors / NMS / proposal上限 | 保持v1及现有训练脚本设置 |
| 阈值选择 | 每轮仅val，在0.1至0.9步长0.1内选择 |
| 模型选择 | val两类精确计数率优先，再较低的平均类别计数MAE，再检测F1；同分保留较早模型 |

| 失败处理 | 如OOM、非有限loss/梯度或执行错误，保留失败记录；不悄悄降分辨率或重启挑结果 |

沿用的模型工厂支持通过kwargs传递上述resize设置，COCO初始化默认可训练backbone最后3个阶段；本轮不更换训练框架。[官方模型文档](https://docs.pytorch.org/vision/0.29/models/generated/torchvision.models.detection.fasterrcnn_mobilenet_v3_large_320_fpn.html)

训练前预计10–15分钟，仅为依据v1耗时和像素增量的估算，实际时间从日志报告。

## 结果

一次运行正常结束，退出码0，训练和逐轮验证总耗时381.34秒（约6分21秒）。训练期间没有改变配置或追加轮次。按预定规则选中第8轮、置信度阈值0.4；第9轮的前三项选择指标完全相同，因此保留较早的第8轮。

| 验证指标（44图、543个目标） | v1：640/960 | v2：960/1280 |
|---|---:|---:|
| 选中轮次 / 阈值 | 10 / 0.5 | 8 / 0.4 |
| 两类数量同时完全正确 | 38/44（86.36%） | 39/44（88.64%） |
| TP / FP / FN | 527 / 7 / 16 | 535 / 3 / 8 |
| Precision | 98.69% | 99.44% |
| Recall | 97.05% | 98.53% |
| 检测F1 | 97.86% | 98.98% |
| bolt计数MAE | 0.1818 | 0.1136 |
| nut计数MAE | 0.1136 | 0.0455 |
| 两类计数MAE均值 | 0.1477 | 0.0795 |
| 逐图记录的模型耗时中位数 | 23.76ms | 35.71ms |
| 12轮训练及逐轮验证总耗时 | 313.33秒 | 381.34秒 |

验证主指标净增加1张（2.27个百分点），误检由7降至3、漏检由16降至8。配对看44张相同验证图：36张两版都计数正确，3张由错变对（ID 89、98、338），2张由对变错（ID 212、361），3张两版都错（ID 1、210、337）。因此，本次改善主要是对象级误检和漏检减少，整图完整计数收益较小；不能描述成所有案例都改善。

耗时仅含单张张量传入、模型预处理/推理/后处理及输出拷回CPU，不含文件解码和KitGuard完整任务流程，也没有单独warmup。两版数值来自不同训练运行中的验证记录，不是随机交叉性能实验，不能直接与原VLM整套观察流程的40.58秒作倍数比较。

以上是用于选模的验证集结果。根代理在第8轮模型及阈值0.4固定后，另行决定对已曝光22图做一次回归；没有根据回归结果改变阈值、模型或训练配置。

## 冻结后的旧22图回归与不晋升决定

回归时间为2026-09-30 04:18:02（韩国时间）。模型SHA-256与上述第8轮 `best.pt` 一致，完整保留22图分母。该集合在v1阶段已经曝光，**这是已有案例回归，不是新的独立测试**。执行前的冻结上下文见 `regression_context.json`，结果见 `regression_v1_test22/metrics.json`。

| 已曝光22图回归（315个目标） | v1：第10轮、阈值0.5 | v2：第8轮、阈值0.4 |
|---|---:|---:|
| 两类数量同时完全正确 | 16/22（72.73%） | **14/22（63.64%）** |
| TP / FP / FN | 302 / 3 / 13 | 304 / 3 / 11 |
| 检测F1 | 97.42% | 97.75% |
| bolt FN | 10 | 6 |
| nut FN | 3 | **5** |
| bolt计数MAE | 0.3182 | 0.3182 |

v2对象级F1略高、总漏检少2件，但两类数量同时完全正确的图少2张，nut漏检增加2件，计数误差增大。这说明对象级平均指标改善可以与完整工单计数可靠性退步同时发生。验证集净增加1张不能代表泛化改善；本次也没有新的独立数据可支持这种结论。

因此不将v2晋升为默认模型。保留v1作为当前实验台默认，v2作为可复现的高分辨率研究候选保留。这个决定同样不代表v1已达到现场可靠性要求：已有22图中v1仍有6图计数不完全正确。后续研究应先补充新来源或真实采集场景，围绕完整计数和错误放行评估；本次未因回归结果开启新训练或重新搜索阈值。
