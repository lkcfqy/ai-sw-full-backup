# 实物验证与比赛演示准备

此文件是待执行的自采实物实验协议，不是已取得的结果。这里的16个开发/48个盲测场景与2026-09-26已建立的公开LOCO 16/48划分是两套不同实验，不能互相充当完成证明。工程自动化测试只能验证流程，不能证明视觉识别准确。

自采照片不是继续开发的前置条件。没有自采条件时，先按 [公开数据开发路线](PUBLIC_DATA_PLAN.md) 使用公开实拍数据进行静态识别评估和流程回放；下述桌面实物实验作为后续可补充的现场验证。

## 后续可补充的桌面实物

四类外观可区分的普通零件，每类最多3个：螺栓、螺母、垫圈、L形角码。每类各拍一张单件参考照片，再使用12格托盘拍整套件。优先选择常见、尺寸接近但视觉特征足够清晰的实物；不要在模型看不清的情况下继续扩大类别。

每次拍照保留真实数量记录，记录者手工数两遍；数量必须独立于模型输出。参考图与开发集允许调提示和拍摄规范；盲测集在冻结版本后才运行。

## 开发与盲测

先采16个开发场景检查参考图、光线、拍摄距离和提示词，修改完成后冻结代码、模型 revision、参考图和相机设置。另拍48个未用于调参的盲测场景：

| 场景 | 数量 | 应检查的行为 |
| --- | ---: | --- |
| 清晰且数量正确 | 12 | 能否产生正确数量，等待人工确认 |
| 少件/多件 | 12 | 能否给出正确增减，不错误通过 |
| 重叠/模糊/局部裁切 | 12 | 是否请求补证或人工核对 |
| 检查后订单发生变化 | 12 | 旧结果必须失效，最新版本重新检查 |

每个场景记录原始照片、人工真值、首次结果、补证指令、执行后的照片、最终结果和用时。不删除失败样本；被迫重启、超时、无效输出和人工接管也计入结果。相同场景比较“清单人工核对”“单次视觉模型检查”“KitGuard补证流程”，比较时保持起始照片及零件状态一致。

## 预先定义的指标

- **错误放行率**：实际数量不符却获得 `ready` 的场景数 / 实际数量不符场景数。人工确认后的错误完成率另列，不能混为一项。
- **完整计数准确率**：四类数量全对且无 `null` 的场景数 / 全部场景数。模糊场景的 `null` 属于保守决策，不算完整计数正确。
- **有效补证率**：初次要求补证且在两轮补证内得到正确可核对结果的场景数 / 初次要求补证场景数。
- **人工接管率、超时率**：各自场景数 / 全部场景数。不可从分母中排除。
- **完成时间**：从开始核对到可确认或转人工的总时间，分别列中位数和最慢场景；模型耗时和操作者耗时可分开记录。
- **版本一致性**：改版后旧检查或旧照片尝试完成必须被拒绝；这项同时由自动化测试和现场操作验证。

不同场景分别报告，再提供整体结果。小样本结果不推广为工业准确率，不把测试集表现写成未来获奖概率。

## 三分钟演示顺序

先展示实际清单与托盘；故意少放一件，展示观察与补件指令；补件复拍后显示可确认。随后用自然语言修改订单并批准，证明旧检查失效；重新检查并完成人工确认，导出带版本和照片摘要的记录。最后展示一个真实遮挡场景，系统要求分开再拍，并给出盲测完整结果及失败例。

需要提前录好备用视频，但现场演示与预录视频应清楚标注。无法稳定通过的实物场景应修复并重新冻结验证，不通过替换假数据掩盖。
