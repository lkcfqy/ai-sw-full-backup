# 最终应用与冻结识别方法的对应检查

正式评测运行于不可变源码副本；后续界面和工作流修复不会自动获得该评测的适用性。最终源码打包前执行：

```bash
.venv/bin/python -m scripts.v07.verify_release_method \
  --run evaluation-runs/v0.7/public_paired_v1 \
  --freeze docs/v0.7/public_paired_freeze_v1/freeze.json \
  --output test-results/v0.7/release-method-compatibility-v1.json
```

命令只接受完整153次运行；输出必须使用新路径。它不加载或调用模型，而是检查：

1. 最终应用的视觉观察、空间计数、双方向一致性、身份核验、模型配置、数据结构、反馈及区域帮助函数8个文件，与冻结文件逐字节一致。
2. 最终 `app.py` 的 `decide` 函数与冻结版本抽象语法树一致。允许文件其他位置存在独立的工作流/路由修复，但不允许借此改变数量决策。
3. 显式构造的 `spatial_guarded` 身份与冻结的模型仓库、revision、协议、模式和1536px配置相同。实际启动配置还需由应用健康信息和演示前检查确认。
4. 所有51张评测图片从**最终应用真实上传路由**重做归一化，与已运行三方法的共同输入SHA完全一致。它不使用重新实现的缩放代码作为替代。

通过只支持“最终应用在上述无参考图、整图、无前序照片条件下仍使用相同识别与判断方法”的结论，不增加样本数，也不证明参考图、人工选区、现场补件或其他域的效果。完整软件回归、异常流程浏览器验收和独立原始记录审计另行执行。

此文档记录验收方法。实际是否通过，以完整运行后生成的JSON为准；文件尚未生成时不能宣称检查已完成。
