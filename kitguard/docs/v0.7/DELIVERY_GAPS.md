审查时间：2026-10-02（韩国时间）。本次只读检查源码、实验计划与既有交付目录，没有运行浏览器或 MLX。下面的“已实现”是代码及其工程记录状态，不表示本次已亲自验证真实界面或模型。主线正在开发、运行的结果，应在取得证据后更新状态。

## 先解决什么

最值得展示的是：**带来源的照片与订单 → 本地模型观察 → 数量差异与下一步 → 订单改版导致旧证据失效 → 明确回放同一照片并重新核验 → 人的数字审核记录 → 可离线复查的证据包。** 这是一项完整的资料审核任务；数量不确定或人工不同意，也能形成清楚的审核结果。

当前最大的交付缺口是新版产品与正式材料不同步。已有 PDF、主 PPT、视频、源码包可以复用结构，但不能作为 v0.7 完成证明。公开数字路线已经足以构成 MVP；增加硬件或虚构现场闭环不会填补下表中的证据缺口。

以下按说明会第7页的实际评分项排序：Agent 实现20、技术实现与完成度20、实用性及效果15、问题/主题15、创新10、数据安全伦理10、商业模式10。它们是官方权重，不是本项目预测得分。[官方规则](https://contest.gnict.org/rule.php)；本地说明会：`../2026庆南AI·SW竞赛资料/09_说明会与培训_20260929/比赛说明会_V0.1_20260929.pdf`（从项目根目录出发），第5、7、14页。

## P1：让评委准确理解价值

1. **问题与适用范围（15分）。** 用“已有照片资料如何在订单改版后保持审核一致”说明需要，而不是宣称替代全部工业质检。当前只支持 bolt/nut/washer/bracket 粗类，每类0–3、总数1–12；螺钉规格、SKU、材质与出库安全不在已验证范围。公开域中的裁剪图与实物现场需要明确区分。
2. **效果指标（15分）。** 机器端耗时、正确可执行覆盖、错误明确输出、弃权/失败及版本错误复用是当前可测指标。没有参与者数据就不写“节省人工时间”“提升现场产能”。51张来自既有两个公开拍摄域；不称独立工厂验证，也不把255种派生 BOM 压力条件当新增图片样本。
3. **创新（10分）。** 自研贡献应落在证据与订单版本绑定、明确弃权、公共图数字审核及可复核导出；视觉基础能力复用 Qwen。条件身份检查是独立实验候选，只有结果支持才能陈述速度/覆盖改善；尚无结果时只介绍研究问题，不列为已实现优势。
4. **数据/伦理（10分）。** 来源链接、CC BY-NC-SA 4.0 与裁剪/回放说明进入报告、包和录像画面。数字审查人代号是自报标签，`user_validation:false`，不能作为≥3名真实用户或机构反馈加分证明。公共数据非商业许可证与未来产品商业假设分别说明，商业落地应使用有权处理的客户数据。
5. **商业模式（10分）。** 可提出“给已有照片和 BOM 的小规模装配/资料审查团队使用的本地软件”，列采购假设、部署方式与待验证收益。收费、客户意愿、ROI、试点方均无实测时明确为假设。无需为填这一页编造客户或收入。

- 为加1分而把演示操作者、合成审核记录或自主代理当成真实用户。真实反馈可另行取得，但不是核心开发前置条件。
