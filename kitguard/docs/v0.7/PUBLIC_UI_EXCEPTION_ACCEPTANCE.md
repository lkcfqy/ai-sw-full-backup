# 公共照片异常流程检查与验收

2026-10-02。范围：公共 catalog 固定来源订单、改版、数字审查、实体完成限制。本轮检查为源码与合成合同验证；没有运行 MLX、浏览器或读取正式评测前缀成绩。真实不确定结果尚须评测结束后的浏览器验收。

## 发现与修复

未发现本轮范围内的 P0。发现并修复一个 P1：公共订单原来显示普通拍照/上传入口，上传另一来源会先使旧核验失效，但随后的数字审查和同图回放因来源不符而拒绝，造成任务无法继续。

修复：`app.py` 在读图、写入前拒绝公共订单普通 `/photos` 上传；`store.py` 在事务内再次拒绝。仅 catalog 创建路由可通过内部初始化参数登记 R1 的首张来源照片，并校验源哈希。事务拒绝后原有异常清理会移除可能已写入的文件。UI 隐藏普通拍照/上传，封住文件选择和拖放入口，显示中韩同图改版重核指引。参考图和区域选择保持既有支持范围，模型方法不变。

已验证：75 个公共审查 API 合同、8 个 catalog 创建/来源合同及 2 个普通订单补证/照片规范化合同覆盖通过；新增用例检查拒绝前后整个订单（revision/photos/checks/public_reviews/epoch/events/status）、照片数据库记录及文件哈希不变，事务二次阻断无孤立文件，参考图仍可添加。初次运行中三个新增测试误把既有审查返回码写为 201，修正为既有 200 后相关六例通过。Ruff、JavaScript 语法及 CPU Node UI 函数合同通过。以上均为合成工程验证，不是模型准确率或真人研究。

## 正式运行结束后：5 步浏览器验收

1. **只运行一次真实不确定候选。** 在新建的一次性公共 `small-part` 任务运行真实模型，可在运行中刷新一次检验任务恢复。保留一次实际结果和耗时，不为获取理想分支反复重试。如果结果不是 `recapture/manual`，如实记录该分支未覆盖。确认没有普通相机/新照片按钮，仍可查看区域和参考图。
2. **补充资料记录不改 AI。** 若出现不确定，确认未知数量显示“—”而非 0、没有就绪/实体完成。记录“需要补充资料”与具体需求，导出确认 AI 原判断未被改写。自动化验收使用 `ENGINEERING-CODEX` 并明确注明工程测试，不能计为真人意见。公共同图重算不算新增现场证据；需要实际新照片的工作应新建自有订单。
3. **旧表单失效。** 在 R1 打开数字审查表单；另一标签页根据预设测试指令显式批准 R2。再提交旧 R1 表单应拒绝，不能增加审查记录。刷新后 R1 核验保留且无效，R2 当前观测为空。改需求只是规则测试，不能解释为解决 R1 缺件。
4. **同图回放仍需新核验。** R2 明确确认沿用同一公开照片后，检查新照片 ID、同像素哈希、状态待检，且 `physical_capture=false`、`requires_new_inference=true`。新模型核验前不可审查为当前结果。实体完工和人工实体复核入口均不出现，导出 `completions`/`manual_reviews` 仍为空。同版本不得再次登记“新证据”。
5. **新修复的拒绝路径与自有订单对照。** 在一次性公共任务拖入另一张照片，应只有固定来源指引且无网络上传/记录变化；直接 API 上传相同或不同来源也应 409 且证据完整保留。随后在一个自有订单上传另一张授权照片，应正常登记并使旧核验失效。此步不需要调用模型；不要在已保存的正式演示订单上试错。

## 保留的边界

后端阻止已登记公共 catalog 来源及已知同源复制链进入实体完成，但哈希不能识别所有未知网络照片、任意图像变换，也不能认证真实拍摄时间或现场事实。数字“需要补充资料”是后续请求记录，不代表资料已取得。泛化到任意授权数字照片的审查流程仍未由当前固定 catalog 模式证明。
