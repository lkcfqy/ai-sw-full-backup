# KitGuard 竞争力独立审查（2026-10-02）

本记录为源码与既有实验材料的只读产品审查；没有运行新模型、采集用户反馈或给出官方评分。软件基线为审查时的 v0.6.0.dev2。建议由主开发线择优实现，下面的候选不等于已经完成。

## 判断

现有优势是能够运行的本地视觉核验、BOM 改版、证据失效、明确弃权及可追溯记录。下一步最有价值的工作是完成公开图片可独立成立的业务闭环，并实验验证推理成本与错误处理；继续增加保护分支、测试数量或报告页数的边际价值较低。

合理定位为：**面向照片资料的备料数量与订单版本审核 Agent，证据不足时明确转交人工。** 公共图片可用作真实模型输入，数字审核结案可形成完整软件任务。不要把不同公开图片说成同一批零件补件前后，也不要把图片审核结案改名为实物出库。

官方通用规则允许公开模型、开源及外部 API，目标为稳定运行至少一条端到端流程的 MVP；并未要求硬件或实体试点。9月29日说明会第7页中，Agent 实现20分、技术实现与完成度20分、实用性及效果15分。第14页 Q7 的真实用户反馈为额外加分，不是实物开发硬门槛。来源：[官方规则](https://contest.gnict.org/rule.php)、[官方主题说明](https://contest.gnict.org/apply.php)；本地说明会 PDF 为 `2026庆南AI·SW竞赛资料/09_说明会与培训_20260929/比赛说明会_V0.1_20260929.pdf`（资料项目根目录下）。

## 仅推荐这三项最高价值改进

### P0：完成公共资料审核的产品闭环

为带来源的图片资料建立独立的数字审核任务：导入图片及BOM → 实际模型观察 → 程序差异核对 → 当前BOM改版或补充资料 → 结案或转人工 → 导出本任务审核结论。终态明确为“图片资料审核完成 / 需补充资料 / 转人工”，保留已观察计数、当前BOM、模型与源图、未确认项；不解除现有实物完成保护。

应复用观察、版本与证据能力，而不是另建一个预填模型答案的演示页。正常数量、缺/多件、BOM改版、资料不足都能形成可解释结果；不强迫每项任务最后变成通过。单张公开图片也能完成数字审核，照片之间没有可证明的现场关联时就不生成物理动作成功结论。

验收以真实应用行为为准：至少一个实际模型端到端任务和一个异常/转人工分支；改版后旧结论失效；结案报告中的来源与当前版本可复查。无需新增大规模通用保护框架。

### P1：把固定昂贵流程改进为有依据的精查策略

先用历史逐阶段日志查清原向、旋转、身份核查分别贡献了什么，再预先固定最小开发实验。可探索单向清单后按可观察条件触发局部身份检查，或用已有独立检测器定位分歧区域作为额外证据；不得用真实标签/期待BOM决定调用分支，也不得因为两类检测器没有输出 washer/bracket 就填0。

目标是找到更好的错误明确、明确覆盖、调用次数与耗时组合，不是证明新组合必然更好。对比同一输入、同一计时边界：完整 guarded、一次清单、候选条件精查。开发样本失败保留，协议固定后在按源图排除所有训练/选型曝光的新数据上再比较。若候选没有改善或证据不足，保留当前默认；实验失败同样是可交代的技术结果。

### P1：完成一个能够证明数字审核价值的公开任务实验

以“能否给出当前版本下正确审核处理”作为终点，构造有作者计数/可核查规则的公开资料任务，而不是继续只统计工程测试。覆盖数量相符、数量不符、BOM改版、证据不足四类；错误规格/SKU明确作为不覆盖或需额外核查的反例，不伪装已解决。

最小比较为：A 单次图像计数+相同程序BOM差异；B 当前完整Agent；C 本轮候选策略。相同任务、BOM和数据范围，统计正确明确处理、错误明确处理、需人工/补资料、失败、全任务耗时及调用次数。单列版本变更后旧结论复用风险与纠正记录。若加“仅规则”基线，输入必须说清：作者真值或人工计数输入的规则只测工作流逻辑，不是能看图的端到端竞争方案；直接使用真值时应标作 oracle 上界。

不能自动生成“人类效率数据”。但真实参与者远程审核公共图片并提供反馈在产品上有意义，不需要实物；这项用户研究仍要由真实人完成，并按数字任务解释其计时与反馈。此阶段先做自主可完成的模型与业务任务实验，不让招募人员成为开发阻塞。

## 不建议本轮优先投入

- 为证明是 Agent 而增加无约束规划器、多Agent角色或更长解释文本；现有可检查的规则决策与状态已经是实质贡献。
- 在同一批曝光图片上继续搜索阈值、训练轮数，然后重新命名为全新测试。
- 在未测完整任务前宣称几十毫秒检测器比40秒完整流程快若干倍，或根据框级精度宣称工单可靠性。
- 为追求“完整工业产品”扩到任意SKU、材质和尺寸认证；当前公开数据与四天左右迭代窗口支持更窄、可验证的数量与版本审核。
- 重写或增加大量交付材料。先完成可运行闭环与真实实验，再用结果更新报告和演示。

## 交付时可说与不可说

可说：本地运行；公开实拍数据；粗类别数量审核；BOM变更后重新核验；明确转人工；实验中观察到的具体错误/覆盖/延迟；数字审核记录可复查。

暂不可说：现场补料成功率；节约工人多少时间；任意工业零件或精确SKU识别；零风险出库；公开数据实验就是企业试点；确定获奖或获奖概率。

本审查没有新造性能数值。上述历史数字来自已有报告，未在本记录中独立重跑或复算。主开发线后续实现应保存新的版本与实验边界，不能倒灌修改 v0.3 冻结成绩。
