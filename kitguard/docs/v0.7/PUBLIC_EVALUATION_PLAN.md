## 问题与边界

比较同一本地 Qwen3.6-27B 4-bit、1536px、同一上传预处理下，独立单次空间清单 `spatial_inventory` 与当前 `spatial_guarded` 的正确可执行覆盖、明确错误、不确定、执行失败、规则错误就绪和延迟。不是四类工业准确率、现场效率或真实出库安全评测，也不保证强化方法得分更高。

新方法如在**既有开发数据**上取得足够依据，可在任何新51图推理前增列为预注册候选；须同步更新冻结方法、执行顺序、分析和接受条件。不得在看过新51图后增改比较方法并继续称未见留出。

## 方法与公平执行

正式运行在冻结代码副本中以 Python `-I` 隔离导入，数据路径显式指向原项目；后续工作区界面或审查功能修改不影响评测。冻结保存所有KitGuard Python模块、静态文件、准备/运行/分析脚本、旧上传runner依赖、模型配置身份与协议散列。运行前检查清单/图像/代码及协议身份；每次观察前再次检查副本代码，变动即停止保留未开始项。

两模式使用同一进程/MLX专用线程，模型全局runtime共享；每张照片单独执行两个完整观察，方法先后按AB/BA交替，51图为26/25。若预先纳入 `selective_identity_experimental_v1`，三方法采用6种排列循环，前3种为循环移位；51图中每方法在第1/2/3位置各17次。绝不把guarded的首轮输出或单段生成时间当成独立基线。每方法均通过隔离的真实app上传路由生成归一化输入，同图各方法输入必须逐字节散列一致。三种观察器共用同一个原始生成记录边界，均保存实际输入、原始模型文本、解析错误和耗时，记录开销纳入各自测量，不修改生产观察器源码。无参考图，不把BOM数量传给视觉模型；温度0、空间清单每方向900 token、条件身份核查1800 token。

不额外以新照片热身，首调用冷启动耗时留在全体记录；保存每次 `loaded_before`，另报告已加载子集，不能只删最慢第一次后报告。计时含每次隔离上传预处理和完整观察，不含参与者操作或实际备料；不能解释为端到端现场工作效率。失败留在分母且不重跑挑结果。中断保留已写入逐例记录，未运行项标N，不伪装为推理失败或安全通过。

## 指标与事先条件

每方法对全部计划51图以及35/16分层报告：C=数量全部正确且可执行，W=明确可执行但计数错误，U=不确定/非可执行，E=执行或输出失败，N=未开始，五项相加必须等于计划分母。提供配对转换表、全体/已加载延迟中位数与P90、最大值和总时长。只作描述性比较，不假设照片统计独立，不给工业置信保证。

数量正确不自动等于C；带不确定/补拍行动的正确数字仍属U。对每图另运行CPU规则面板：全部255种合法四类BOM，以及来源支持的15种两类或63种三类BOM，排除与真值一致的BOM。记录每图是否存在任意错误 `ready`，不能用成千上万容易拒绝的订单稀释风险。生成的BOM是规则压力条件，既不是作者真实订单，也不增加图片样本数。无输出/执行失败的图明确标风险未测，不将其零次放行解释为安全。

本轮保守接受条件：完整51图分母；guarded E=0、W=0、any_false_ready=0；C至少90%（即46/51）；相对单次清单最多损失3张C；包含冷启动的中位测量时间≤60秒。只有同时通过这些条件，并相对基线严格减少W或存在错误就绪的图片，才称“本组照片观察到描述性安全收益”；两者均零错误时不声称强化流程证明有优势。条件不是工业标准，也不自动改变产品默认或晋升训练检测器。负结果同样保留。

**候选后续验证门槛，亦在新图推理前固定：** 若单方向身份核查候选被纳入，先通过相同完整分母、零W/E/any_false_ready、90%覆盖和≤60秒门槛，再要求其C不少于当前guarded、包含冷启动的中位时延≤guarded的80%（至少降低20%），且guarded比较记录全部完成。全部通过也只标记“可进一步验证”，不自动晋升或改变默认；未通过时保留负结果。该条件不能由更快但损失正确覆盖的结果满足。

## 可重复命令

数据已经准备，生成器拒绝覆盖现有输出；只有需独立重建时指定一个新v0.7目录：

```bash
.venv/bin/python -m scripts.v07.prepare_public_evaluation --output datasets/derived/v0.7/public_paired_rebuild
```

待开发候选决定、最终脚本和方法确定后，仅冻结，不运行模型：

```bash
.venv/bin/python -m scripts.v07.run_public_paired \
  --create-freeze \
  --manifest datasets/derived/v0.7/public_paired_v1/manifest.json \
  --freeze docs/v0.7/public_paired_freeze_v1/freeze.json
```

只有在旧开发28图结果支持、主任务决定纳入候选后，在上述冻结命令增加 `--include-selective-identity`；该选择写入冻结文件，运行阶段不能临时增加。

由主任务独占MLX后执行；命令自动从冻结代码副本启动：

```bash
.venv/bin/python -m scripts.v07.run_public_paired \
  --freeze docs/v0.7/public_paired_freeze_v1/freeze.json \
  --project-root . \
  --output evaluation-runs/v0.7/public_paired_v1
```

输出 `run.json`、两方法102条或三方法153条计划观察的 `predictions.jsonl`、逐生成原始文本/实际输入、归一化输入、清单/冻结副本以及 `analysis.json`。失败/中断时条目可能未满，分析保留计划分母；任何再次尝试都必须另建清楚标记的诊断运行，不能覆盖首次结果。

本次软件测试仅覆盖计划排程、源图去重选择、旋转框裁剪边界、全分母/缺失/失败、错误就绪面板、结果身份错配与重复，以及基线无错时不虚构收益；不代表识别结果。
