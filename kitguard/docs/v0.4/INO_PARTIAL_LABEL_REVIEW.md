# InO-10-190：仅作者 L-bracket 数量有标签的独立审查

初版 2026-09-26；补充 2026-09-27（韩国时间）。初版只读作者说明、本地来源/分组/标注统计及现有计数协议，没有看图片、跑模型、补标或修改推理代码。数据来源固定为作者提交 `c733a3543157135c591cbe3f9de27e209964af63`。初版是实验设计；文末另列冻结执行记录与运行后的 A41 语义复查，避免把事后发现当作事前规则。

## 标签能支持什么

作者 README 列出 L-bracket、U-bracket、angle bracket 等十类，不能由这些标签推出 KitGuard 的 bolt、nut、washer 均为零。现有 `spatial.py` 的 bracket 定义为 L-shaped support，因此将作者 class 0 作为 L-bracket 阳性检验对象有明确文本依据；它仍是作者类别到本产品粗类的映射，不能把其余未映射类别自动判成负类。

本地统计：每套 origin/cropped 各 190 张、919 个标注对象，class 0 共 80 个、出现在 62 个来源图中。作者 README 写 920 个对象，报告应保留“作者说明 920；本地固定标注解析 919”的差异，不自行增加第 920 个标注。origin/cropped 对应同一批 190 个来源，不是 380 个独立来源。A–F 分组和相邻拍摄可能相关，也不能把每张都自动视为独立抽样。

建议单独 partial-label manifest：

```json
{
  "label_scope": "author_class0_L_bracket_count_only",
  "ground_truth": {"bracket": 2},
  "unlabeled_parts": ["bolt", "nut", "washer"],
  "author_class_id": 0,
  "source_id": "author-source-id",
  "full_inventory_truth_available": false,
  "business_release_evaluation_available": false
}
```

其中 2 仅示范字段形式，不是实际案例。未标注类别应缺省并显式列为 unlabeled；不要填写 0，也不要复用预测字段中的 `null` 来伪装四类真值。**不能调用当前 `evaluation.score_case/order_tasks`：它们要求完整四类整数真值，并会生成 matched/mismatched 订单。** 新 runner 可以调用原观察器和原 Observation 结构验证，但必须使用独立单类计分器，不制造 BOM、不运行业务放行计分。

## 主指标与输出行为必须分开

令 N 为模型运行前固定入选的全部来源图数量。每张最多产生一条最终结果，不因重试、旋转、身份裁剪或派生订单增加 N。

| 主终态 | 定义 | 是否计入 N |
| --- | --- | --- |
| `C_b` | 最终 `observed.bracket` 为整数，等于作者 class 0 标注数量 | 是 |
| `W_b` | 最终 `observed.bracket` 为整数，不等于作者标注数量 | 是 |
| `U_b` | 完整观察结构有效，但最终 `observed.bracket` 为 null | 是 |
| `E` | 执行、超时、解析或 Observation 结构验证失败；优先于残留部分输出 | 是 |

主指标叫 **“作者 L-bracket 计数一致率：C_b/N”**，同时报 W_b/N、U_b/N、E/N；保证四项之和为 N。整数计数完全相同但全局仍被阻断，可以计 `C_b`，但不能改称“正确可执行”。失败不能依靠残留原始输出获得成功计分。作者数量不一致率 W_b/N 与已给出整数中的不一致率 W_b/(C_b+W_b) 同时报告，零分母为 null。W_b 不自动等于视觉误分类；作者实例标注范围与产品全图粗类别范围可能不同，见文末 A41 复查。

另计算一个纯输出属性：

`app_clear = 四类预测均为整数 && issues为空 && action.kind为none`

按 `C_b/W_b/U_b/E × app_clear/blocked_or_failed` 列交叉表。可单列“作者角码数量相符且应用输出清楚”数量，但 **app_clear 不证明另外三类正确，不等于订单 ready、四类完整准确或安全放行**。例如 bracket=2 与作者一致、nut=null：属于 `C_b + blocked`；bracket=1 但模型输出完全清楚：属于 `W_b + app_clear`。其他三类的输出保留原样，只作未经真值评判的诊断。

首轮与强化结果可在同一张入选图片上各按上述单类终态计分，并列转换表，明确来自同次相关调用。不要把“强化使 nut 不确定但 bracket 仍相符”误报为角码计数退化；应用清楚度变化在交叉表中体现。延迟单独给 N、执行失败数、中位数/最大值和计时边界，不把缺失/失败耗时写成零。

本批没有 class 0 为零的预定负样本，**不能报告无角码图片的假阳性率/特异性**。不能报告四类完整正确、正确补件、错误 ready、人工完成安全或连续实物作业效率。不要和原64张不同标签范围的结果合并成一个准确率。

## 预定 ROI 的选择效应与复现要求

拟采用的规则是标签驱动的 **已知目标位置 ROI**：作者 L-bracket 数量 1–3；每个 class 0 框原始像素短边至少 32；取所有 class 0 框的 union，加 union 短边 10% 的边距；任何作者框越界则整个 source 排除；ROI 与任何非 0 框接触/相交都排除；作者标签仅有 class 0 时保留选定版本全图。

这些规则适合作为补充阳性诊断，但会排除小目标、混杂与标签越界来源，并利用人工标注定位目标、移除干扰、放大目标。**它不评估系统自动发现 ROI 的能力，也不等于原始广角场景的检测能力。** 不能说“图片里确定只有角码”：只能说“ROI 没有与作者已标注的其他类框相交”；框外或未标注物体的真实类别未知。

运行前必须冻结以下细节并保存筛选清单：

- origin/cropped 的固定优先顺序；同一 source 最多选一个版本/ROI。不得看模型结果后挑更好的版本。使用作者 cropped 全帧时，明确它本身是作者裁剪版，不叫原始相机全视野。
- YOLO 坐标转换、32px 判定在缩放前进行、union 边距、左上向下取整/右下向上取整、图像边界裁剪、相交判定使用最终实际 ROI。边界接触是否排除必须固定；当前“不碰”应采用接触也排除。
- 所有标注框的有效性检查在 ROI 筛选之前进行。任一版本的作者框越界即整个来源排除这一较严格约束，应和被排除 source/reason 一起保存，不事后对困难样本放宽。
- 保存原图/标注 SHA、作者类别和框、实际像素 ROI、变换后 SHA、来源组、排除原因、1/2/3 个角码的层数分布及全帧/ROI 数量。筛选仅用固定标签/几何信息，不咨询模型。

报告主标题建议：**“InO-10-190 作者定位 ROI 中 L-bracket 阳性计数诊断（其余三类未标注）”**。如果仅有少量纯 class 0 全帧，单独列全帧结果，不能用 ROI 的较好表现替代全帧表现。

冻结方法后一次运行、保留全部失败；没有事前效果门槛时只作描述性新域诊断，不事后制定“通过标准”。本次图在运行后即已暴露，若据其错误调整提示/裁剪/阈值，则后续只称开发回归，另设新来源验证。模型预训练是否接触过这些公开图片未知；“本项目此前未评测”不等于“模型从未见过”。
