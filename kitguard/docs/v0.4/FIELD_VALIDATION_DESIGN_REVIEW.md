# v0.4 现场验证工作台：最小协议独立审查

2026-09-26。依据 `docs/REAL_WORLD_VALIDATION.md`、`docs/v0.3/FINAL_EVALUATION.md`、当前 `schemas.py`、`store.py`、`evaluation.py`。本文是实施建议，不是已执行实验或认证；不改变 v0.3 冻结推理方法。范围限定为“一次固定实物状态/图片、一个固定订单版本、一个人工或 KitGuard 核对试次”，优先把分母、时间与证据记录做对。

## 1. 最小状态机与证据边界

建议独立 `field_trials` 表/模块，由现有 Store 只读取得订单、照片、核验和事件；不直接改写订单的 `ready/completed`。工作台“结束试次”不等于实物完工。

`draft → locked → running → completed | abandoned | failed | interrupted`

- **draft**：填写场景、匿名操作者代号、来源、人工真值及目标 BOM；可修改。所有四类真值是严格整数，允许 0，不可把 `null` 当 0；不要直接用要求总数至少 1 的 `Requirements` 校验空托盘真值。
- **locked**：服务器固定真值、目标、来源、条件与协议版本，记录 UTC 时间及规范 JSON SHA。冻结后无修改/删除接口；发现真值录错，保留并附加纠错说明，另建关联试次。原试次仍显示且不能被悄悄排除。
- **running**：服务器原子开始计时并进入“全部开始试次”分母。绑定一份当前订单/版本/证据 epoch/起始照片快照。KitGuard 模式不得利用开始前已产生的 check；在锁定前已有核验的场景，标为已暴露回放，不能声称前瞻评测。并发重复开始只返回同一记录或 409。
- **completed**：人工模式只接收操作者提交的计数/判断；KitGuard 模式只接收 `check_id`，由服务器解析真正保存的 check。成功结束仍可能是错误计数或要求补拍；“completed”只表示试次记录完整，不是“识别正确”。
- **abandoned / failed**：用户放弃必须填写原因；请求失败、模型失败、超时保留已开始试次与原因。没有模型 check 的失败不能填造一个预测。重启遗留 running 标 `interrupted`；未终止试次也在导出分母显示，不自动忽略。

连续补件每次会改变实际真值。此最小版本必须结束当前固定状态试次、独立登记新状态并锁定后才再核验，用 `parent_trial_id` 关联；不能拿起始真值给补件后照片打分，也不能用最终 ready 反推补件成功。两轮补证率和实体完成收益留到有逐步真值协议后计算。

### 三种来源，禁止互相升级

| source_kind | 可证明的范围 | 必须显示的限制 |
| --- | --- | --- |
| `self_reported_physical` | 自述现场 + 软件内实际工单/照片/check 关联 | 拍摄和真值独立性由操作者声明，软件不能证明现场真实性 |
| `public_replay` | 已知公开图的流程回放 | 不算自采、真人实物补件或新独立样本 |
| `engineering_fixture` | 模型替身/自动化工程验证 | 不进入真实模型或真人效果统计 |

保存原始声明和服务器判定两列。订单有 `demo_source` 时强制 `public_replay`；check 的 `backend=test` 时强制工程身份或拒绝进入真实模型分层。用户选择“现场”不能覆盖这些事实。同一图片重复上传、同一来源裁剪和同场景两种模式是相关数据；报告并列试次数、唯一照片 SHA 数、声明场景数，不相加充当独立样本。

## 2. API 最小字段与锁定规则

| 操作 | 客户端字段 | 服务器必须生成/核验 |
| --- | --- | --- |
| `POST /api/field-trials` | `label, operator_alias, condition(manual/kitguard), source_kind, source_note, scene_id, pair_id?, parent_trial_id?, truth_counts, truth_method, truth_independent_declared, requirements` | 严格模式、长度/计数约束；`id, created_at, protocol_version`；禁止接受客户端得分/耗时/派生来源 |
| `POST /{id}/lock` | 预期记录版本；明确确认 | 固定内容 SHA、`locked_at`、不可改；真值和目标分离 |
| `POST /{id}/start` | `order_id, expected_revision, photo_id?` | 读取并保存订单快照、要求一致、demo 身份、版本/epoch、照片 SHA、先前核验暴露情况、`started_at`；持久化后才返回 |
| `POST /{id}/finish` | 人工 `reported_counts, reported_decision`；AI 仅 `check_id`；人工接管声明与原因 | 实际 check 必须属于该订单、该版本、该 epoch/照片、发生在开始后且结束时仍有效；保存观察原文、backend、模型身份、事件及其 SHA；派生计分和服务器耗时 |
| `POST /{id}/abandon` | `reason` | 终止时间、状态和全分母记录 |
| `GET /api/field-trials/report` | 可选来源/模式筛选 | 完整已登记/锁定/已开始/终态数量、每行状态、全部失败； JSON/CSV 导出应带协议和数据边界 |

真值只存在验证模块，不进入视觉提示、模型请求或普通工作台结果；在试次执行页默认隐藏，结束后才能并列计分。单机同浏览器没有独立账号隔离，即使隐藏也只能称“结果前锁定”，不能称盲测。人工计数者与真值登记者若同一人，显示可能记忆偏差；两种模式共享真值或场景不证明严格公平对照。

第一次开始后不得切换模式、目标、来源、真值、工单或照片。最小方案对版本/照片变化使试次无法正常完成，并保留 `failed` 原因；重新核验需新试次。普通浏览器提前知道的模型结果无法被软件彻底侦测，因此“未先看模型结果”永远是声明，不得自动生成“独立真值已证实”。

持续时间由服务器计，不接受客户端 `elapsed_ms`。采用同进程单调时钟计时，UTC 用于审计；重启中断不得用负值归零或假装连续秒表。至少分别列“试次总耗时”和 check 保存的“模型耗时”，不把服务器计时叫纯人工操作时间。人工终止的计数不等于独立裁判结果。

## 3. 报告口径与必测断言

主要分母是 **全部已开始试次**；同时列已锁未开始、未结束，防止挑选成功记录。按来源 × 模式分层，工程记录默认与效果表隔离。0 个试次显示“尚无数据”，比例为 `null`，不能显示 100%。

- 完整正确率：四类全等真值且没有阻断问题的试次 / 全部已开始试次。人工称“提交计数与登记真值一致”，不称模型准确率。错误明确、未知/补拍、执行失败、放弃、未结束各列互斥数量，和必须等于分母。
- 错误就绪率：真值与固定目标不符却返回 `ready` / 所有已开始的真值不符试次；另列失败、未知、放弃数量。`decision=correct` 在现系统是“需增减调整”，不是“模型回答正确”。
- 时间：完成、失败、放弃各自 N/中位数/最大值；未结束为右删失/进行中，不参与完成时间中位数但保留分母。只比较成功者的耗时必须写“成功试次条件下”，不得据此宣称整体提效。
- 成对比较：只对事先共同 `pair_id` 且两种模式均启动的场景列原始差值和缺失数。未建立真实随机/交叉顺序、独立操作者和相同起始实物状态时，不宣称因果提效或严格用户研究。现有 64 图结果独立保留，不混入现场分母。

必要工程断言：

1. 锁定后不能改真值/来源/模式/目标；额外字段、bool 计数、null 真值及客户端时间/得分被拒绝。
2. 并发开始/重复结束无重复行；终态不能重开；重启后 running 可追踪，不删除失败。
3. 旧 check、其他订单 check、开始前 check、换图/改版/参考变化后的失效 check、客户端伪造观察均不能完成 AI 试次。
4. 真值从未出现在模型输入；实际 check 的来源、backend、照片 SHA、版本和需求全部由服务器取得。
5. 公开演示和 test backend 不能进入真实现场/真实模型统计；公开图手工上传仍只能凭用户声明判断来源，报告披露此边界。
6. 非成功和未结束均计入分母；零样本率 null；同照片多试次不增加唯一照片 N；全部类别和分母守恒。
7. 导出保留锁定快照/事件/实际 check/失败/派生规则，输出按数据转义，操作者只需别名；散列说明为内容完整性而非身份签名。

**建议本轮验收标准**：实现可运行登记→锁定→计时→真实 check 绑定/放弃→分层导出，完成以上工程断言，并提供显著标为工程演练的演示记录。真实现场结果仍显示 0，直到用户实际执行；这比自动生成看似漂亮的“真人效果”更能支撑答辩。

实现契约复核补充：当前落地采用 `/api/studies`，一批固定图片人工先、AI 后，整批关闭才揭示真值；与本文通用建议字段名称不同。root 已采纳重点测试项：登记、冻结、每次开始均检查既往 `inspection_started`；人工阶段发生推理不得正常完成；每种终止（含失败、放弃、关闭、恢复中断）均保留窗口内全部实际事件/check，报告额外统计已返回错误与错误 ready，避免看见错误后选择“失败”隐藏证据；进程 nonce 变化使时长未知而非伪造连续计时。两次相同输入仅是重复人工录入，不证明独立计数者。
