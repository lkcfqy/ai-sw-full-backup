### 1. ChatGPT에 사진을 올리거나 사람이 세면 충분하지 않나요?

소량 부품은 사람이 더 빨리 셀 수 있습니다. 현재 사람보다 빠르거나 정확하다는 실험 결과는 없습니다. 저희가 구현한 부분은 사진 답변 뒤의 작업 흐름입니다. 작업지시 수량과 사진 버전을 묶고, 불명확하면 보완 촬영을 요청하며, 수량 차이를 계산하고, 오래된 사진·수정 전 지시서로 완료 처리되지 않도록 검사합니다. 판단과 실패 이력도 내보낼 수 있습니다. ChatGPT 단독 사용과의 직접 비교는 아직 하지 않았습니다.

中文要点：价值在工单、照片、补证和完成记录的约束；不能说比人工快，也没有做 ChatGPT 对照。

근거: [작업 흐름 코드](../../kitguard/app.py), [증거·버전 검증](../../kitguard/evidence.py), [현장 검증 설계](FIELD_VALIDATION_DESIGN_REVIEW.md).

### 2. 로컬 27B 모델이 너무 느리지 않나요?

빠른 연속 생산라인용이라고 주장하지 않습니다. MacBook Pro M5 Pro 64GB에서 Qwen3.6-27B MLX 4-bit를 사용했습니다. v0.3 공개 실사 64장에서는 전체 관찰 중위 40.58초, p95 49.69초, 최대 52.50초였습니다. 사진 처리·저장·관찰을 포함하지만 사람의 촬영·판단 시간은 포함하지 않으며, 전체 HTTP 응답시간과도 구분합니다. 별도 실제 API 예시는 15.91–51.49초였습니다. v0.4의 작은 작가 지정 ROI가 포함된 20장은 중위 11.529초였지만 입력 구성이 달라 속도 개선의 근거로 비교할 수 없습니다. 현 단계는 낮은 처리량의 확인 업무를 위한 연구용 프로토타입입니다.

中文要点：公开64图中位约40.6秒；新20图约11.5秒主要受输入构成影响，不能当作提速实验。3080台式机没有本次实测成绩。

### 3. 같은 모델을 두 번 호출하면 독립 검증인가요?

아닙니다. 같은 모델이 원본과 90도 회전 입력을 보고, 필요한 경우 너트·와셔 후보를 추가 확인합니다. 관찰 사이의 오류는 서로 상관될 수 있습니다. 기록에도 `same_model_correlated_calls=true`를 남깁니다. 두 결과가 같아도 정확하다는 보장은 없으며, 불일치나 식별 불확실성은 미확정으로 남기는 장치입니다. 서로 다른 전문가나 독립 모델의 합의라고 소개하지 않습니다.

中文要点：同模型相关调用，只帮助发现部分矛盾；一致不能证明正确。

### 4. 신뢰도, 오류, 판단 보류는 어떻게 구분하나요?

보정된 확률형 신뢰도는 제공하지 않습니다. 평가에서는 명확하고 맞는 결과 C, 명확하지만 틀린 결과 W, 확인 불가 U, 실행 실패 E를 구분하고 실패도 전체 계획 분모에 넣습니다. v0.3 고정 64장 결과는 C/W/U/E=59/0/5/0이었고, 같은 실행의 첫 관찰은 62/2/0/0이었습니다. 두 오류를 보류했지만 맞았던 세 장도 보류하는 비용이 있었습니다. 관찰된 W=0은 실제 오류율 0의 보장이 아닙니다. 화면의 ‘수량 조정 필요’나 `correct` 상태는 인식 정확도 판정이 아니며, `ready`도 사람의 실물 확인을 대신하지 않습니다.

中文要点：无校准置信概率；错误、弃权、执行失败各自保留。宁可弃权有成本；64图零明确错误不等于真实风险为零。

근거: [C/W/U/E 결과](../v0.3/FINAL_EVALUATION.md), [평가 정의](../../kitguard/evaluation.py), [상태 구조](../../kitguard/schemas.py).

### 5. ㄱ자 브래킷의 새로운 데이터에서는 무엇을 확인했나요?

InO-10-190의 작가 class0 개수만 정답으로 사용했습니다. 나머지 세 제품 범주는 미표기이며 0으로 채우지 않았습니다. 사전 고정한 20장은 작가 개수 일치/불일치/미확정/실패가 16/2/2/0입니다. 작가 위치를 이용한 ROI 16장은 16/0/0/0, 전체 이미지 4장은 0/2/2/0이므로 반드시 나누어 제시합니다. 20장 모두 정답이 1이어서 항상 1이라고 답해도 20/20입니다. 별도로 사전 고정한 F/52 두 개 ROI 1장은 일치했지만, 항상 2라는 답도 그 한 장에서는 맞습니다. 일반적인 수량 추론 능력이나 현장 성능을 입증한 결과가 아닙니다.

A41은 작가가 아래쪽 대상 하나만 표시했지만 모델은 위쪽 고정용 지지물 두 곳도 ㄱ자 브래킷으로 세었습니다. 작가 개수와의 불일치는 유지하되, 이를 곧바로 시각적 오분류나 허위 탐지라고 부르지 않습니다. 모델의 전체 이미지 범주와 작가의 대상 인스턴스 범위가 다를 수 있습니다. 이 해석은 실행 후 AI 보조 검토이며 정답을 새로 만든 것이 아닙니다. `app_clear` 역시 출력의 명확성일 뿐 네 범주의 정확성이나 출고 허가가 아닙니다.

中文要点：仅作者角码数量有真值；主20为16/2/2/0，整图与已知位置ROI必须分开。A41存在标注对象范围差异，不能将不一致直接解释为视觉错认；单个双角码例子不能证明多件稳定性。

### 6. 직접 만든 부분과 외부 자산은 무엇인가요?

기반 모델을 훈련하거나 공개 사진을 직접 촬영했다고 주장하지 않습니다. 공개 모델·라이브러리 위에 작업지시/증거 버전 제약, 공간 물체 목록과 프로그램 계수, 보완 요청, 완료 트랜잭션, 실행 기록·검증기·증거 묶음과 사용자 화면을 구현했습니다. Codex가 코드·테스트·문서 생성과 검토에 사용되었습니다. 여러 AI 에이전트의 교차 검토도 AI 보조 검토이지 독립적인 사람의 감사가 아닙니다.

MVTec Screws/LOCO의 저자 사진·라벨과 InO-10-190 저자 저장소를 사용하고 출처·라이선스·고정 revision·SHA를 보존했습니다. MVTec 자료의 CC BY-NC-SA 4.0 조건과 InO 저장소의 MIT 조건을 구분합니다. 해시 일치는 파일 및 기록의 내부 일관성을 확인할 뿐 저작권 판단이나 실물 현장 진정성을 인증하지 않습니다.

中文要点：贡献是可执行工作流和证据约束；基础模型、作者照片、Codex辅助开发均披露。AI交叉审查不能称独立人工审计。

### 7. 실제 작업자나 공장 검증은 몇 건인가요?

현재 실제 작업자 현장 비교 실험은 **N=0**입니다. 공개 사진의 모델 실행, 합성 입력의 브라우저 자동화, 스크립트가 채운 수동 결과 칸은 사람의 실험이 아닙니다. 현장 검증 기록기는 독립 정답을 먼저 등록하고 계획된 수동→AI 순서, 사진/지시서 버전, 반환된 결과와 실패·포기를 남기도록 구현했습니다. 그래도 물리적 현장이라는 운영자의 진술 자체를 인증하지는 않습니다. 실제 실험 전에는 절감 시간·불량 감소율·고객 도입 효과를 제시하지 않겠습니다.

中文要点：真实人员现场样本仍为0；记录器已实现不等于现场验证已完成。公开回放和工程夹具明确标识。
