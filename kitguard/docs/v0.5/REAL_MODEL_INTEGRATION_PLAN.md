# v0.5 真实模型连接验收计划（尚未冻结/执行）

本计划用于新区域管线的真实连接检查，不是新holdout、四类准确率测量或真人研究。实际执行前必须再保存固定JSON清单、确切图/标签SHA、全部实际源码SHA及源码快照；此预备文档本身不表示已经跑过。

## 两个固定输入与一次调用

1. InO A/41 原作者PNG。输入先走真实上传，再选择作者class0完整bbox外扩短边10%（向下/上取整），作为明示的作者定位开发区域。原v0.4整图已有输出且已人工看图，所以本次只作开发集成。拟定BOM为bracket1、其他0，仅是要求，不冒充另三类真值。运行一次真实inspect，保留实际结果、scope、根图/派生图和工单证据ZIP。不得做字段填零的四类评分，不点击实物完成。
2. 既有 mixed-screws 公开开发样例，作者四类真值3/0/0/0。用官方公开图库创建fresh工单，选择与完整图同边界的region，以检查区域派生字节与lineage、field登记冻结和实际MLX的连接。整个范围仍包含作者原图全部物体，故沿用其公开真值。创建public_replay研究，人工栏脚本输入作者真值，明确不是真人。先冻结，再一次inspect并绑定实际check；关闭后导出JSON/HTML/含根图和派生图的ZIP。整框案例用于流程，不宣称去背景收益。

每例最多一次inspect，不重试、不选择好答案；返回不确定或错误照常留存。HTTP请求数与内部多阶段生成次数分别记录。API前置工程错误可以在任何模型调用之前修复并留下记录；任何实际调用后不得删除重跑。

## 必须验证

- 正式执行期间无人改源码、没有第二个GPU任务；固定27B/revision、1536、spatial_guarded，四个观察方法模块保持v0.4原样。
- API前后根JPEG与来源图/上传归一化字节绑定正确；区域JPEG从根图按固定整数边界/95编码独立重建相同SHA。
- actual check.inspection_scope 与当时已声明范围一致；整图/派生是一个source family，不能计作两张新实物照片。

- field导出由独立 verify_study_export.py 重算，通过只说明内部一致性与协议绑定，不认证真人、照片真实性或范围完整性。
