# v0.5 操作者指定检查区域：最小设计提案

状态：设计建议，尚未实现；不修改 v0.4 源码、交付、历史成绩或冻结评测。默认仍核验整张照片。不增加框架，不自动检测 ROI，不重新训练模型。

## 要解决的问题与取舍

A41 的作者标注针对目标角码，顶部固定装置中的角码可能不属于作者的目标集合，而当前应用观察整幅图。全图观察与作者指定目标范围不同，不能单凭“作者1、模型3”就断言模型多检了两件。反过来，也不能以作者框裁剪后回答1来证明应用能自动识别待检范围。

最小新增能力是：**操作者在调用 AI 前声明本工单的检查范围，并让系统一直保留范围之外的原图证据。** 模型仍只负责观察这个已声明范围；它不负责证明框外没有遗漏的待检件。

先只做轴对齐矩形，默认 whole-image。暂不做多框、自由多边形、旋转框、自动框选、跨图拼接或类别过滤。一次核验只对应一个明确范围和一个工单版本。这样可以复用现有相片核验管线，同时把新增风险集中在“范围是否完整”及“派生图是否可追溯”。

## UI 最小流程

1. 主工作台上传或拍摄完整场景后，照片工具区提供 `검사 범위 / 检查范围`，初始标记 `전체 사진 / 整张照片`。不会因为看到框或上传完成就自动推理。
2. 打开原有样式的原生 `<dialog>`。主视图始终是系统保存的完整照片；可在图上拖动矩形，框外只加半透明遮罩，不从画面消失。并提供“整张照片”按钮。
3. 同一对话框提供四个可键盘输入的整数边界字段：左 X、上 Y、右 X、下 Y。显示完整图的 W×H、选区宽×高，以及“右/下边界不包含”的简短帮助。纯键盘用户不必使用拖动；数字输入可用上下方向键步进1，Shift辅助步进10可后续增加，不能成为基础可访问性的前提。
4. 小尺寸预览标记 `같은 사진의 선택 영역 / 同一照片的选区视图`，与完整原图同时可见；不能标为“新拍照片”。放大只是显示操作，不改变源坐标或图片字节。
5. 提交选区前，操作者显式勾选：

   > 이 주문의 검사 대상 부품은 모두 영역 안에 있으며, 경계가 부품을 자르지 않습니다. 영역 밖의 고정구·배경은 이번 검사 대상이 아닙니다.
   > 本工单的全部待检件都在框内，边界未切断待检件；框外固定装置与背景不属于本次待检对象。

   这是操作者声明，不是软件认证。未勾选不能应用选区。
6. `범위 적용 / 应用范围` 只保存范围并使旧核验失效；之后由用户再次点击核验。取消对话框不产生 API 修改。保存期间禁用重复点击。
7. 当前照片是选区派生图时，再次打开选择器仍加载它的完整根图，并回显根图坐标。允许从同一根图重新选择或恢复整图，禁止在上一次裁剪图上递归裁剪。
8. 工作台保留明显的范围条：`选区核验 · 框外未核验`，以及“查看完整照片”。AI 的 ready 显示“选区内数量与要求一致，框外未核验”；最终人工确认仍需要核对实物，不能自动出库。

移动端把原图、选区预览、四个数字字段纵向排列。源坐标始终按实际图像内容区域计算，不能把 object-fit 留白、边框、CSS 缩放、滚动偏移或设备像素比当成图片像素。拖动转换可用 min 边界向下取整、max 边界向上取整，结果必须在数字字段中可检查。服务端不默默修正越界值。

## “原图”的准确含义

v0.4 当前保存的是经过 EXIF 方向纠正、RGB 转换、长边不超过2048、去除元数据的 JPEG；原上传文件仅有 `source_sha256`，其原始字节没有保留。因此此功能的根图是**本系统保存的完整归一化照片**，不是声称保留了相机 RAW/原始 EXIF。

源坐标就是这张已存根图的整数像素坐标。UI、API、导出都必须采用同一定义。不能在客户端原文件的8192像素坐标中选框，却在服务端2048像素 JPEG 中裁剪。

## 建议数据模型：根照片 + 不可变派生视图

为了最少改动现有“最新照片 ID → 核验”的管线，建议派生视图作为 `order.photos` 中的新条目保存，但明确它不是新的物理照片。普通相片是根条目；派生条目直接指向根。现有缺少以下字段的历史记录解释为普通根图，不回写旧档案。

根图新增概念（历史兼容可在读取时补默认值）：

```json
{
  "id": "img_root",
  "kind": "root_photo",
  "root_photo_id": "img_root",
  "root_photo_sha256": "sha256-of-stored-normalized-full-JPEG",
  "source_family_sha256": "sha256-of-stored-normalized-full-JPEG"
}
```

选区视图条目示例（下面数字仅说明格式，不是 A41 的实际区域）：

```json
{
  "id": "img_region_view",
  "kind": "inspection_region_view",
  "sha256": "sha256-of-exact-derived-JPEG",
  "root_photo_id": "img_root",
  "root_photo_sha256": "sha256-of-stored-normalized-full-JPEG",
  "source_family_sha256": "sha256-of-stored-normalized-full-JPEG",
  "root_width": 1600,
  "root_height": 1200,
  "region_xyxy": [180, 240, 1420, 1120],
  "coordinate_space": "normalized_root_pixels_xyxy_half_open_v1",
  "derivation": "pillow_root_crop_rgb_jpeg95_v1",
  "scope_declaration": "operator_all_required_items_inside",
  "scope_confirmed_at": "server timestamp",
  "root_created_at": "original stored-photo timestamp",
  "created_at": "derived-view timestamp"
}
```

`sha256` 仍指实际模型输入视图字节；根图 SHA 与 `source_family_sha256` 用于照片来源族的绑定。三者用途不同，不能把裁剪字节不同等价为新增实物证据。哈希仍不证明拍摄时刻、实物状态或操作者身份。 这个来源族仅覆盖系统已知的派生链；操作者在外部软件裁剪后重新上传，若没有可信链路，系统无法仅凭不同哈希识别为同一实景。不能声称已经阻止所有外部裁剪伪装。

whole-image 不做重新编码，继续使用完整根图的精确已存 JPEG。恢复整图可追加一个 `kind=inspection_region_view`、`region_xyxy=null`、`scope_mode=whole_image` 的不可变视图，字节直接复用根 JPEG；这样不用允许任意历史照片绕过“当前最新照片”检查。正常新上传且没有选区时仍走原来的 whole-image 路径，避免改变默认推理输入。

最小版本可延用当前 JPEG 处理方式：从根 JPEG 解码后按整数边界 crop，RGB、JPEG quality95，无缩放放大，不从派生图再解码裁剪。需要记录编码方法及派生文件 SHA；不能称为无损裁剪。若未来改用 PNG，应作为另一种明确版本并同步图片 MIME/存储实现，不在本次悄悄混用。

## 一个新增修改端点

建议 `POST /api/orders/{order_id}/inspection-region`。正文不上传客户端裁剪图，不接受文件路径或任意 URL，也不接受客户端预测/真值。

```json
{
  "expected_revision": 3,
  "expected_photo_id": "img_current_root_or_view",
  "expected_evidence_epoch": 7,
  "root_photo_id": "img_root",
  "mode": "region",
  "region_xyxy": [180, 240, 1420, 1120],
  "confirmed_all_items_inside": true
}
```

- `mode=whole_image` 时 `region_xyxy=null`。`mode=region` 时边界为四个严格整数，拒绝 bool、float、字符串、NaN 等；`0 ≤ x1 < x2 ≤ W`、`0 ≤ y1 < y2 ≤ H`，选区两边至少32像素，与当前图像最低尺寸规则一致。很小的区域可以提示清晰度风险，但本次不增加未经评测的自动质量认证。
- 服务端按当前 photo 向根图解析，校验传入根图确实属于此工单及该当前视图，且不是参考图、其他工单照片或另一派生图。不能只相信客户端声明的 root ID。
- 根图版本必须仍适用于当前工单；工单改版后不得用“选择旧图区域”绕过现有重新上传/拍摄要求。合法重新上传也只是一次来源声明，不自动证明实物发生变化。
- 同一事务中核对 revision、当前 photo ID、evidence epoch、当前无 active inspection、非已完成工单及无未关闭 field 绑定。核验进行中拒绝修改，不等推理结束后偷偷套用旧请求。
- 读根文件先校验真实字节 SHA、维度与元数据相符；生成临时派生文件，再原子写入视图与事件。如果并发校验失败，清理临时文件；不要留下无主照片。
- 成功返回 `{order, photo, changed:true}`。已经处于同一根图/同一范围且并发令牌当前有效时可返回 `changed:false`，不重复加历史。失联后的重发若令牌过期，返回409，前端重新读取并展示实际范围，不能自动再次推理。
- 保存动作增加 `evidence_epoch`，使所有旧有效 check 失效，状态回到待核验；记录 `inspection_region_selected` 事件，包含前后 view、根图 SHA、整数边界和声明时间。不要伪造 `photo_uploaded`/`new_capture` 事件。

现有 `/inspect` 可继续接收当前 `photo_id` 和 `expected_revision`，服务端照常在开始/结束检查 evidence epoch；check 快照增加 `inspection_scope`，保存根图、选区、派生视图和声明。任何派生文件/根图被更换或区域重新选择，都不能让旧结果继续完成工单。

## 必须一起处理的来源与反馈语义

这是最容易出现的实现漏洞，不能只做前端 crop：

1. 现有反馈按 JPEG SHA 区分“新证据”。派生视图的 SHA 会变化，所以必须另外按 `source_family_sha256` 判断是否新拍摄。重选、整图→裁剪→另一裁剪→恢复整图，全部属于同一根图族。
2. 范围变化可以得到一次新的**同源视图观察**，不能计作一次“补拍成功”、新的独立图片、已移动实物或新的 field 样本；也不能重置不确定补证预算。
3. 对同一根图族的变体，不生成“新照片解决了旧问题/新增零件”的反馈。最小版本直接显示“范围已改变，结果仅适用于当前区域”，并从反馈上下文中排除不同坐标系的旧 region。
4. 公共图来源、许可证和原 `demo_source` 继承到所有派生视图；裁剪不能把公开图变成 `self_reported_physical`，也不能消除此前观察记录。
5. 输出空间点、模型建议补拍区域、90°方向验证与身份 crop 坐标仍在当前输入视图坐标系中。主结果默认叠在派生视图上。若要叠到完整根图，必须使用确定性平移/缩放映射，并明确标记；绝不把视图坐标直接画到根图上。`check.action.region` 是模型建议，不是本次操作者检查范围，两者使用不同字段与文案。
6. 模型仍不能看到目标数量、作者真值或旧预测。选区功能只改变输入图像及其来源绑定，不借机把期望计数加入视觉提示词。

## 与 field 冻结的配合

必须在**登记案例之前**确定范围，而非看到模型输出后再裁去“错误”部分。

- 案例绑定：除现有工单版本、photo ID/SHA、reference、evidence epoch，再封存 root ID/SHA、根图尺寸、整数边界、派生视图 SHA、来源族、范围完整声明。真值定义为预先声明的检查范围中的待检件；操作者仍要确认本工单全部待检件都在该范围内。
- 顺序：新照片 → 选区声明 → 独立真值两次输入 → 案例登记 → 全部案例冻结 → 人工 → AI。人工和 AI 必须使用同一个冻结范围；人工计数界面也显示完整根图加选区。
- 为适配 v0.4 案例不可编辑/删除的协议，**案例一旦登记，直到批次关闭，该工单的范围修改就拒绝**。不仅 frozen，draft 中已登记案例也锁定，否则用户会把不可编辑的批次卡死在过期绑定上。
- 登记前选错可修改；登记后不能修剪同一照片再当成新的首次现场样本。关闭旧批次会保留其未开始/失败分母；继续真实前瞻性现场采集需要新拍照片与新声明。普通非研究工作台可在旧批次关闭后重选，但历史案例与旧图字节保持原样。
- 同源曝光/重复规则改按根图族校验：一个派生视图已被 AI 观察，则同根的整图、其他裁剪、其他工单中的同源复制都不能冒充未观察的现场输入。不同选区也不能各自增加独立样本 N。
- 作者提供的 ROI 可用于明示的 `public_replay` 诊断，不能声称来自用户成功框选、自动定位或真人实测。A41 及全是1角码的20例，不因此变成泛化计数验证。

## 导出必须可独立复核

工单证据包与 field 证据包都同时包含：

- 完整归一化根 JPEG、实际交给模型的派生 JPEG（whole-image 可共享同一字节文件）；
- 根图/派生图各自 SHA、尺寸、根图的源上传 SHA（若存在；派生图不虚构一次新上传哈希）、坐标约定、边界、编码方法、照片族、声明与范围变更事件；
- HTML 中完整原图、可见选区框和旁边/下面的派生图；标注“同一照片派生、框外未核验”；
- 检查结果、冻结绑定与原历史事件，完整保留范围修改前的失败/不确定记录；
- 原始公共来源与许可证。去 EXIF 的根 JPEG 不能标成相机原始文件，裁剪生成时间不能标为拍摄时间。

导出时按现有方式重新计算根文件与派生文件哈希，不匹配就拒绝打包。独立校验器验证图片绑定、坐标边界与冻结快照；若以当前编码器重建派生图，应固定并记录编码版本。跨版本重编码未必逐字节相同，不能仅凭文件扩展名或视觉相似通过。校验字节与几何不代表认证操作者声明或框外没有遗漏。

## 实现前应冻结的最小验收门槛

1. 整图默认路径和原 JPEG 字节不变；无选区时既有工作流继续通过。
2. 鼠标拖动、触控和纯键盘数字输入得到一致根坐标；320/390/桌面、长宽不等图、object-fit 留白和滚动下不漂移。
3. 拒绝空框/越界/小数/布尔值、跨工单/参考图/递归根引用、过期版本/epoch、进行中推理和未关闭 field 绑定。
4. 从当前裁剪重新选择依旧从同一根图生成；整图→A→B→整图不会增加新的实物证据数，不报告补拍改善。
5. 重新选择后旧 check/完成操作被拒绝；重发、丢响应与并发标签页不会悄悄保存两种不同有效范围。
6. field 真值、范围与模型实际输入完全对应；首次人工/AI之后无法利用新 crop 隐藏既有观察或扩大 N。
7. 证据包在离线浏览器可同时查看根图和选区，所有文件 SHA、坐标、模型输入与来源都能核对。
8. 先以明确工程夹具验证软件，后以新真实材料评价操作者是否能正确划定范围。不要复用已看到的 A41 去宣布无偏准确率提升。

这项功能把“哪些零件属于这张订单”交给操作者明确声明，并让审查者看得到被排除的部分。它能缓解范围不一致，但不能替代现场任务定义、完整性确认或真实泛化评测。建议 root 先批准这一最小范围，再实现与单独版本的验证。
