# KitGuard 발표 대본과 질의응답

9장 발표자료 대응. 목표 6분, 질의응답 2분. 아래 시간은 연습용 배분이며 실제 발표 속도를 측정한 결과가 아니다. 105초 설명 영상은 별도 시연 자료다. 발표 중 전부 재생할 경우 말하는 분량을 줄여 총 6분에 맞춘다. 실시간 모델 실행에는 약 50초씩 걸릴 수 있다.

## 1장 / 25초

안녕하세요, 해피 팀입니다. 저희의 KitGuard는 사진과 주문 수량을 함께 검토하는 로컬 AI Agent입니다. 사진을 분석한 뒤 검토자가 어떤 위치를 확인했고 어떤 결론을 내렸는지까지 한 작업에 남깁니다. 기존 Mac과 공개 사진으로 실제 동작하는 디지털 MVP를 구현했습니다.

## 2장 / 35초

교육 키트나 소규모 조립 업무에서는 사진과 수량표가 따로 전달될 수 있습니다. 사진은 같은데 주문이 바뀌면, 이전에 확인한 결과를 그대로 써도 되는지 알기 어렵습니다. KitGuard는 사진과 주문을 함께 등록하고 현재 버전의 근거를 보여줍니다. 이 대상 업무의 실제 수요와 효익은 앞으로 검증할 가설입니다.

## 3장 / 35초

실제 실행 사례입니다. 첫 주문은 나사류 세 개, 너트 두 개, 와셔 두 개를 요구했습니다. 로컬 모델은 각각 두 개를 관찰했고 프로그램은 나사류 한 개 차이를 안내했습니다. 저장된 관찰 시간은 55.052초입니다. 이미 개발에 사용한 공개 사진이므로 이 시연을 새 정확도 평가로 계산하지 않았습니다.

## 4장 / 50초

모델은 원방향과 회전 사진에서 물체 목록을 생성합니다. 조건이 충족되면 너트와 와셔의 국소 영역을 더 확인합니다. 그 다음 Python 도구가 목록을 세고 현재 BOM과 비교합니다. 주문 정답 수량은 시각 모델에 입력하지 않습니다. FastAPI와 SQLite는 검사 작업과 버전, 사진 해시, 의견을 저장합니다. 자유롭게 계획하는 범용 Agent는 아니며, 정해진 정책에 따라 도구와 상태를 연결하는 작업 Agent입니다.

## 5장 / 45초

이번에 추가한 핵심은 그림 위 복검입니다. 검토자가 물체의 위치와 범주를 표시하면 프로그램이 수량을 계산합니다. 원래 AI 결과는 바꾸지 않고 별도 결론을 남깁니다. 확인하기 어려우면 추가 자료를 요청할 수 있습니다. 화면의 여섯 표시는 자동화 조작자가 기능 리허설로 입력했습니다. 실제 사용자가 참여했다거나 표시가 자동으로 인증된 정답이라고 주장하지 않습니다.

## 6장 / 50초

다음은 주문 변경 시나리오입니다. 필요한 나사류를 세 개에서 두 개로 명시적으로 바꾸면 과거 검사와 결론은 현재 근거에서 제외됩니다. 같은 사진도 새로 연결하고 다시 추론합니다. 두 번째 관찰은 49.773초였고 새 복검도 주문 수량과 일치했습니다. 사진 속 부품을 보충한 것은 아닙니다. 내려받은 증거에는 각 버전, 원 AI 관찰, 복검 위치와 수량, 이유가 남아 있습니다.

## 7장 / 50초

검증의 분모를 구분해 공개했습니다. 기존 공개 51장에서 정확 41, 오류 3, 보류 7입니다. 추가 LOCO 조합 24장에서는 정확 23, 보류 1이지만 같은 도메인의 제한된 결과이며 기존 세 오류는 남아 있습니다. 소프트웨어 회귀는 1,826개 통과했습니다. 이 숫자는 상태와 API 계약 검사 수이며 모델 정확도가 아닙니다. 실제 참여자와 현장 효과는 아직 측정하지 않았습니다.

## 8장 / 35초

첫 도입 가설은 한 담당자의 사진 검토 업무입니다. 로컬 설치, 업무 양식 설정, 유지보수 계약을 수익 방식으로 생각하고 있지만 가격과 구매 의향은 검증 전입니다. 고객이 권리를 확보한 사진으로 기존 방식과 비교하여 전체 시간, 놓친 차이, 잘못된 일치와 도움 요청을 측정하겠습니다. 연구 자료의 비상업 조건도 유지합니다.

## 9장 / 35초

개발은 9월26일부터 시작했으며 기존 관찰과 증거 엔진의 재사용을 공개합니다. 대회 기간에는 복구와 자료 주문, 개정 재검사 등을 추가했고 10월3일에는 위치 복검 결론과 만료 처리를 구현했습니다. Codex를 코드와 자료 제작에 활용한 사실도 공개합니다. 현재 자가평가는 Level3 MVP입니다. 다음 단계는 실제 담당자의 독립적인 업무 검증입니다. 감사합니다.

## 예상 질문

**Q. 기존 챗봇에 사진을 보내는 것과 무엇이 다른가요?**

A. 구조화 관찰 뒤에 주문 버전과 근거를 연결하는 상태 처리가 있습니다. 주문이나 의견이 바뀌면 결론이 만료되고, 복검 위치와 원 AI 결과를 각각 저장합니다. 답변 텍스트를 넘어서 다음 작업과 기록을 관리하는 것이 이번 구현의 차이입니다. 시장 전체의 독창성을 입증한 특허 주장으로 확대하지 않습니다.

**Q. AI가 틀리면 결국 사람이 다 세야 하는 것 아닌가요?**

A. 현재 범위에서는 확인자의 판단이 필요합니다. AI가 먼저 차이와 불확실성을 제시하고 확인자가 근거를 남기는 구조입니다. 사람이 세는 시간을 줄였다는 효과는 아직 측정하지 않았습니다. 전체 작업시간과 오류를 기존 방식과 비교해야 합니다.

**Q. 왜 실물이 없나요?**

A. 현재 작업 범위를 사진 자료 검토로 정의했습니다. 공개 사진과 기존 장비로 입력부터 결론·기록까지 실행할 수 있습니다. 이 결과를 실제 부품 보충이나 출고 검증으로 표현하지 않았습니다.

**Q. 무엇을 직접 개발했나요?**

A. 공개 모델을 연결한 주문·사진 스키마, 상태 관리, 공간 목록 계수·비교, 해시 결합, 실패 복구, 위치 복검과 증거 화면을 구현했습니다. Codex 코드 생성·검증 도움을 광범위하게 사용했습니다. 기반 VLM을 직접 학습했다고 주장하지 않습니다.

**Q. 1,826개가 모두 실제 사진 테스트인가요?**

A. 아닙니다. 대부분 API·입력·상태·저장 계약을 확인하는 소프트웨어 테스트입니다. 모델 사진 평가와 실제 MLX 시연은 따로 보고합니다.

**Q. 24장에서 오류가 없으니 안전한가요?**

A. 한 도메인과 특정 조합의 제한된 결과입니다. 보류 한 장이 있고 기존 51장의 세 오류도 남습니다. 독립적인 현장 신뢰성으로 일반화할 수 없습니다.

**Q. 주문을 줄여서 통과시킨 것 아닌가요?**

A. 주문 변경 시 과거 근거가 무효화되는지 보여주는 예정된 기능 시나리오입니다. 고정된 주문의 부족분을 해결했다고 주장하지 않습니다. R1 차이 기록을 지우지 않고 남겼습니다.

**Q. GPU나 인터넷이 꼭 필요한가요?**

A. 현재 Mac의 기존 통합 GPU와 저장된 모델로 추론했습니다. 외부 GPU와 클라우드 API는 사용하지 않습니다. 최초 환경·모델 준비는 별도이며 소스 ZIP에 큰 모델 가중치는 포함하지 않았습니다.

**Q. 실제 사용자가 검증했나요?**

A. 아직 없습니다. 화면과 기록에 기능 리허설과 ENGINEERING-AGENT라고 표시했습니다. 다음에는 실제 담당자가 독립적으로 수행하고 실패와 도움 요청까지 포함해 측정하겠습니다.

**Q. 상용화는 가능한가요?**

A. 현재는 연구·디지털 보조 MVP입니다. 연구 사진의 비상업 조건을 유지하고, 고객이 권리를 확보한 자료로 효과와 정확도를 검증해야 합니다. 다중 사용자 보안과 운영 체계도 후속 개발 범위입니다.
