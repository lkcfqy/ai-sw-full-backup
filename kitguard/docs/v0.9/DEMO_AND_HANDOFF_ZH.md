# 无实物演示与交接

当前版本dev4使用[最终操作指南](../scoring/DEV4_HANDOFF.md)，支持自己的照片与BOM目标；新版五件套在output/competition-final-dev4。以下dev3路线作为历史操作说明保留。答辩采用docs/scoring/PRESENTATION_SCRIPT_KO.md，未宣称实际真人彩排。

## 启动

现有电脑双击项目内 `启动参赛演示.command`，或运行 `bash scripts/run_competition.sh`。它使用现有虚拟环境和项目内 `models/Qwen3.6-27B-4bit`，数据写入独立 `data-competition-v09/`。旧模型目录的兼容链接已删除，启动器直接使用项目内路径。浏览器打开 http://127.0.0.1:8765 。已有8765服务时先确认页面版本，不要启动重复服务。首次加载模型有等待，界面显示真实进度；不需要外部GPU或新购买部件。

全新解压的源码不附环境和模型；先按根 README 的 setup 说明安装依赖并准备相应本地权重。已测试的是现有依赖下源码解压启动，不是没有依赖的新机器一键安装。

## 当前单人演示路线（dev3）

1. 打开[自主审查台](http://127.0.0.1:8765/static/autonomy.html)，选完整演示，点击开始。无需准备实物、参与者或人工示范答案。
2. 实际模型自动处理三种公开开发照片。数量差异保留差异清单；小零件不确定时请求更多资料；不会硬改成成功。
3. 展开“计划、工具与分支依据”，讲清目标、每步工具、当前订单/照片绑定、从实际检查选择下一步。规划采用明确规则，视觉观察由本地MLX完成。
4. 第三场景的R2是开始前固定的模拟订单变更。系统先使R1失效，明确复用同图，然后运行新的R2推理；不是补了实物，也不是AI擅自改需求。
5. 页面刷新后执行继续。停止按钮仅停止后续步骤，已开始的模型推理需结束后释放资源。服务重启保留中断记录，整次耗时记为未知；不暗中续跑或伪装成功。
6. 结束后下载证据ZIP，打开index.html查看原图、AI/BOM、版本与工具轨迹，mission.json保存完整检查快照，SHA256.json用于文件校验。检查包在后续订单变动后仍保留当时快照，并标注当前绑定已经历史化。

正式6分钟展示可在开始推理后讲解问题与架构，再展示真实保存的结果。如果采用剪辑视频，明确删去了等待时间。图上独立复核仍可在订单详情中演示，但不要求其他人参与。

### 已实现的可选任务对照记录器

1. 打开[公开照片任务对照](http://127.0.0.1:8765/static/digital-trials.html)。一人一个匿名编号P01、P02，不填姓名、学号或联系方式。
2. 真人本人选择“真人自愿试用”、阅读说明并同意。顺序号决定手工/AI先后及照片轮换。当前不招募参与者，此说明仅保留模块操作方法。不要只留下完成或表现好的参与者。
3. 一人六项任务：数量差异、小零件复核、订单改版，分别用手工和KitGuard。开始才显示照片与要求；用时包含模型加载、等待、审查、改版和提交，没有暂停按钮。
4. 改版任务先保存R1回答，再揭示R2。AI方法必须重新执行当前版本模型；仍可对模型观察提出不同的最终数量与结论。不要告诉参与者作者标签或示范答案。
5. 每个人最后关闭记录，下载JSON；失败、放弃、中断和未开始均保留。六任务只算一人。结果先报告正确/错误/未确认和版本错误，再报告总耗时中位数、配对差值与帮助按钮使用次数。这里的帮助次数不是第三方人工求助人数。
6. 结束后问本人三件事：哪一步最容易错、哪项证据最有帮助、是否愿意用来审查类似图片。保留原话，并说明其实际背景；普通学生试用不代表工厂员工或市场需求。不要把小样本、重复开发照片的结果写成因果提效或新图准确率。

若手工更快，原样报告。可以强调可追溯性或版本约束，但只有真人数据支持时才能说减少错误。若无人参与，明确写“真人0，尚无提效证据”，继续用工程闭环参赛；工程演练用途一旦创建不能改为真人。
