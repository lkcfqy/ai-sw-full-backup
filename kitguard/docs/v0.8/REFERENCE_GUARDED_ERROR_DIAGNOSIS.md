## 类别、定位与图像细节分别说明

四例中冲突的原作者 ID 均为 `type_007`：217 的两个环分别是 annotation 217004、217008，120 是 120004，024 是 24004，172 是 172003。217 中模型甚至对同一作者类的两个实例分别给 washer 和 nut。项目按已有 Neuromatch 教学别名将 type_007 投影为 nut；MVTec 原始 COCO 只写 type_ID。详见[语义来源审查](SCREWS_CATEGORY_SEMANTICS_REVIEW.md)。这仍是原冻结投影下的四个 W，不能因模型或本次目检更像 washer 而事后改标；同样不能把它夸大为已独立认证了物理螺母材质或内螺纹。

九张实际输入的有限目检显示：各裁剪都包含对应环状物，未见整个目标被裁断或裁剪成邻近另一物体；背景在孔中可见，环边缘有强反光，部分内壁细节有限。放大裁剪只是 LANCZOS 插值，不增加原照片中没有的螺纹/厚度信息。`through_hole` 支持“孔”这一几何判断，不能单独区分有内螺纹的 nut 与无螺纹的 washer。现有身份提示已要求不可见的 threading/outline 使用 uncertain；本轮输出仍全部确认，不能声称仅再写一句“注意螺纹”已有成功依据。

**172 另有点定位缺陷，不能把四例都称为定位正确。** 按冻结 `identity.py` 的像素换算 `x*(W−1), y*(H−1)`，原向点 `[0.81,0.87]` 在 1152×864 输入中为 `(932.31,750.81)`；作者框中心是 `(933.196,799.195)`，相距 **48.393 px**，超出约 65×63 的原作者框。原点位于环的上方背景，身份裁剪 `[828,647,1036,855]` 仍完整包含环，所以模型可从裁剪中的环给出 washer，但其输出没有落实“只判断所给点”的约束。旋转点更接近该环。172 的旧新身份裁剪 SHA 完全相同，仍给同样类别；增加空间参考没有消除这个问题。

其余三个样本的环点都落在各自原作者框内（217 两点距框中心约 8.4/6.0 px，120 约 15.6 px，024 约 25.0 px）。因此，修复点定位即使对 172 有帮助，也没有证据支持它能解决另外三例类别冲突。原始框仅用于本次事后诊断，不能注入候选推理或拿来为其挑选目标。

## 一个最小下一候选建议

若继续检验参考机制，建议仅预注册一次 **“原 G 两方向观察保持无参考，只在身份阶段追加同一对已冻结类别参考”** 的独立实验臂。这样检验的是参考的参与阶段：本轮空间参考未挡住任何原 W，身份阶段则尚未接收这对参考。参考必须明确不计数、保持与目标/裁剪不同索引；不得传入真值、作者类别、期望数量或先前正确答案。既有“类别冲突只置 unknown、不修正计数”的规则继续适用。这是待验证假设，不是已发现有效修复，也不自动授权模型运行或生产更改。

实验前固定唯一候选、参考 SHA、目标/裁剪映射和完整评分合同；完整跑旧 51 一次作开发回归，报告全部 C/W/U/E/N、旧正确损失、14 个 LOCO 旧 C 与全四类 false-ready。不能只跑四个 W、按其成绩换参考/调提示，也不能把 Screws 没有 washer 阳性当成“washer 输出一律拒绝”的依据。新 24 的准备与独立协议仍保持分离。本诊断不足以支持重训、自动 nut↔washer 改数、追加旋转多数投票或候选晋升。

完整参考实验的全四类 false-ready 是 **4/51**；source-supported 面板的 0/51 不代表整体为零。旧 51 当前已是开发数据，文件中历史 `split=holdout` 字段不构成新的未曝光评测。
