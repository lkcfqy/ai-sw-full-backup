## 方向一：物体级参照检索，先检验身份表征再考虑融合

**优先研究；预计 1–2 个工程日原型，时间只是预算，不是交付承诺。** 用冻结视觉编码器把单件候选裁剪与小型已批准类别图库进行显式相似度比较；返回最近的 nut/washer 示例、分数与间隔，并允许 unknown。这与把参考图交给语言模型重新描述不同：类别证据变成可重算的图像距离；把定位误差与身份表征失败分别记录。先用本地 OWLv2 视觉编码器固定一种特征提取法，不同时试多个模型/池化方法。

首个可证伪实验只做**组件级身份诊断**，不触碰旧 51：从已曝光 train 来源按预先写出的 source/hash 规则准备最多 16 个图库裁剪；按源分组留出最多 64 个已曝光开发/验证裁剪，类别平衡，另保留 bolt/印刷标识等拒绝对照。Screws 框可来自作者；LOCO 无作者实例框的补充裁剪必须明确为新 AI/人工开发标注并先审查，不能冒称原作者框。图源及其裁剪不能跨图库/校准/评估角色。精确清单必须在任何嵌入结果之前固定；本稿没有选图。

预算：**最多 128 次裁剪编码、一个固定 encoder、零微调、一个预先规定的拒绝阈值选择规则、30 分钟计算上限**；到时未完成计 N，不重启挑成功子集。展示每类 C/W/U/E/N、来源组指标、常答 nut/常答 washer/全拒绝基线。先在校准角色选一次阈值，再完整评估；若评估任一方向仍有明确错类，或每类正确覆盖不足 75%，或背景/bolt 对照误接收，则停止该原型，不继续扫图库与阈值。小样本通过也不是安全性证明。

通过组件测试后，才值得另立整图候选：使用独立检测器的完整候选区域，**不靠 VLM 点选框、不给作者框做生产 ROI**；参照身份冲突只能将已有类别置 unknown，不自动改数。完整旧 51 仅作一次最终开发回归，沿用 W/E/N=0、C≥41、14 个 LOCO 旧 C 全保留、全四类 AFR=0。若未过，保存失败而不对这 51 张继续调参。

风险：视觉特征仍可能记住背景/颜色或预训练偏差；一张特定 SKU 参考不能认证整个 nut 类；LOCO 小件与 FOD 小目标的裁剪信息本来可能不足；新框可能把塑料印刷当物体。该方向的价值是让这些假设单独接受检验，不是把相似度包装成正确概率。

## 方向二：增加真实视角的信息，而非重复旋转同一像素

**优先作为补证交互研究；不保证降低当前 51 错误。** 对 nut/washer 身份任务固定要求一个主视角和一个额外视角，明确两图是同一对象记录，不增加计数。Agent 创建补证任务、绑定原图/对象/订单版本、收齐后调用身份工具，并保存原判断与新证据；分歧继续 unknown。重裁、旋转或插值同一张照片不能冒称新视角。

先用本地 MANTA 的 train 开发来源做单件机制验证：若另获批准，事前按记录 ID 固定最多 **20 个对象记录（两类各10）**，同一记录所有面板合组；固定第0与第2面板，不按预测选择“最好看”的视角。作者描述和已看四例支持横向五面板，但仍须逐记录检查布局，camera 实际方位未知；布局无法验证的记录保留失败，不换图。新记录成为开发曝光，不动作者 test/FOD held_back/LOCO24。两臂为第0视图单图身份和第0+第2视图联合身份；最多40次调用、同一输出 schema/模型/预算、无重试，计算上限45分钟。

主要结果是对象级 C/W/U/E/N 与配对变化，不是“总数恒为1”的计数成绩。预先定停止条件：若单图已经全对，记“无改善空间”，不宣传收益；若双图不能降低 W、或 C 减少、或使原 C 变 W，则不集成。记录“多视角”与作者同一记录关联，不称独立物理件认证。MANTA 黄绿 washer 与银色混放差异大，即使通过，也不能据此宣称修复 Screws/LOCO。

真正落到订单流还需要**同一件的可靠关联和额外材料**。现有 [regions.py](../../kitguard/regions.py) 只是同一原图的区域声明，不应改名当新视角。缺新图、图源关系不明或标签只能人工确认时，界面保留“补充资料/人工确认”，不可把人为改答案当模型成功。真人试用若尚未发生，继续报告用户验证为0。

## 对比赛展示的四项具体价值

1. **版本化参照图库**：能展示每个身份结论实际比较了哪个示例、文件 SHA 和适用类别；不只展示聊天结论。
2. **可检查的对象清单与冲突**：框/裁剪/参照距离分开呈现；冲突触发补证，原始错误与拒绝记录保留。
3. **有来源的补证任务**：主图、额外视角、订单版本和批准事件绑定；需求变更后旧证据失效，禁止为了变绿改 BOM。
4. **完整效果与成本面板**：把错误、拒答、额外调用和操作者负担同时报告；阴性研究结果可展示，但不冒充现场收益或人评。

这四项是最多增加的展示能力，不是四项均已完成。若身份新机制仍无有效证据，优先完成现有数字审查/补证/批准/导出闭环与真实用户试用；不要再用一串同 51 数据上的改 prompt 结果充当进步。
