# 下一版感知建议：优先三类检测器，整图独立定位

2026-10-02；有界只读工程评审。未训练、未运行 MLX/检测器、未改冻结代码与证据。**建议推进 FOD + Screws 的 bolt/nut/washer Faster R-CNN 开发，先做影子结果；不再重跑旧两类否决，也不把 MANTA 单件得分当混合 BOM 成功。**

## 具体改什么

三次 G 错误不是简单缺少一次复核：原向、旋转、同一 Qwen 身份检查共同把冻结映射为 nut 的 type_007 认作 washer。旧两类检测器确实给三个对象产生了高分 nut 框，但基于 Qwen 点的否决漏掉两例（点在框顶外 7.43/16.74 px）；它又把 LOCO 的 washer 纳入 nut，造成 14 个旧正确图变 U。[完整负结果](HETEROGENEOUS_VETO_RESULT.md)

下一版必须从**完整原图直接产出对象框和三类类别证据**，不以 Qwen 的点或类别选择 ROI。在独立实验脚本中复用现有 Faster R-CNN MobileNetV3 FPN 和 v1 backbone/RPN/ROI 表征，将背景+bolt+nut 的 3 输出头扩为背景+bolt+nut+washer 的 4 输出头；显式复制旧三行分类/框回归权重，新 washer 行按固定种子初始化，记录所有未加载/新参数，不能用含 shape 冲突的 `strict=False` 冒充成功加载。新增 worker/schema 留在 v0.8，旧两类脚本和生产观察接口不改。

检测器从整图找对象，NMS 与阈值在开发/验证组固定；不按 BOM 限制框数，不依 Qwen 判断合并邻件。最初只输出独立三类清单、框、分数、重复/漏检诊断。接入候选时先保守：可靠且已去重的 nut/washer **存在数量下界**超过 G 的该类数量，才将相关类别置未知；不能把未检测到当 0，不能替换成“修正后的正确数量”。这样有机会覆盖旧 G 的 nut=0 错误而不再依赖偏移的 washer 点。三类检测器不支持 bracket，不能默认为 0。异构权重摆脱了同一 Qwen 的自我复核，但错误/预训练数据仍可能相关，不叫统计独立真值。

## 数据可行性与最主要风险

| 本地资产 | 可用方式 / 风险 |
|---|---|
| Screws 214 train / 44 val，现有作者框转换 | 保留旧 source 分组、taxonomy 和框转换，提供 bolt/nut 及混合两类场景；已用于开发，绝不重新称留出 |
| FOD 精确来源恢复 6740 图，2 个歧义匹配排除 | root 已授权本地监督研究；不分发图像，不声称商业许可。不能沿用原逐帧 split |
| 保守分组后 | bolt 7 组、nut 3 组、washer 4 组。GOPR 同视频前缀合并；DJI 同类合并；未知无前缀同类合并。只能称记录来源组，不能认证不同物理件 |
| FOD 分辨率 | 全为 300×300；作者框短边中位数 nut 13.89 px、washer 14.64 px，最小约 4.03/3.37 px。放大不会创造螺纹/厚度细节；低分辨率不确定是合理输出 |
| 真正的混合三类场景 | FOD 候选全部只标一个目标；LOCO 已曝光图有真实 bolt/nut/washer 混放，但目前只有数量真值，没有完整实例框。不能只靠 FOD 单件分类正确来证明混合计数 |

先按上述来源组固定 train/val/test，再看训练侧少量按固定间隔取的图核对 XML 框、resize、类别定义和标注完整性；对每个组设同样的取样上限（建议首轮最多 24 帧，按原 frame 序列均匀间隔，禁止邻帧随机分组）。Nut 仅 3 组意味着每个角色只有约 1 个 FOD 来源组，不能把 1303 帧包装成泛化样本量。保留组级指标；同组近重复只降低权重，不增加 N。

必须先确认 FOD 框是整图中所有可见的支持类别对象，还是仅被跟踪的一个目标；若存在未标注同类物体，不能把它们作为背景训练整图检测器，应补开发标注或将该源限为对象裁剪分类用途。Screws 桌面、FOD 路面、LOCO 透明袋的背景差异会造成类别—数据源捷径，尤其 washer 主要来自 FOD。按类/来源平衡采样，采用预注册颜色扰动/灰度开发对照，保留真实 LOCO 银色 washer 负控；MANTA 的黄绿 washer 不能替代这一负控。

## 最小执行顺序与止损条件

1. 做三类新 manifest 与 group split 审计，明确每个 source 的角色；训练/验证/测试图片和来源 SHA 全绑定。沿用 Screws 214/44；FOD 只从训练组核对框和开发。训练轮数、随机种子及阈值选择规则先写协议，验证按类别和来源组宏平均，不让帧数最多的组决定阈值。
2. 做一次有界三类微调，记录每轮 train/val；只用新验证组选 checkpoint/阈值。当前本地 torch 2.14.0、torchvision 0.29.0、v1 权重与 COCO 初始化缓存都在，无需模型下载。模型训练逻辑可复用 [现有训练器](../../scripts/train_public_detector.py)，但硬编码二类限制与输出头须在新实验文件中明确更新。
3. 冻结候选后，在**已曝光旧 28 和旧 51 分别**做完整开发回归，分别报告定位/身份/整图三类数量，以及融合 C/W/U/E/N、四类规则面板 false-ready、LOCO 误拒与新增耗时；不合成 79 个“独立新样本”。如要量化 LOCO 定位，应先对已曝光开发组补齐逐实例框并记录人工来源，不能拿 Qwen 点当定位真值。
4. 开发进入下一阶段的建议门槛：旧 51 的 W/E/N=0、主面板 false-ready=0、C≥41，LOCO 原 14 个 C 全保留；旧 28 的 W/E/N=0、C≥24。任何一项未过，保留负结果，不接默认链。只修三个错误或提高 FOD 单件分数不算通过。通过仍只是开发资格，随后需要新来源的多件混合数量变化场景；MANTA 仅可补身份异域诊断。

这一路径对混合 BOM 的作用，是把“独立对象在哪、是什么、是否重复”变成可核对的框与类别清单，再由规则计算差异。没有完整对象召回与混放验证，不能把类别头增加 washer 直接解释成安全盘点。

## 暂不优先的替代路线

本地也已有 OWLv2 与 Grounding DINO 权重及 transformers 5.17.0，可做无额外下载的开放类/图像参照实验。但原完整开发 28 图的整图计数为 OWLv2 0/28、DINO 1/28，已有大量多框、误分类和漏检。[OWL](../v0.3/OWL_DEVELOPMENT_REPORT.md)、[DINO](../v0.3/GROUNDING_DINO_DEVELOPMENT_REPORT.md)。用 OWLv2 图像嵌入给独立 detector ROI 做 nut/washer/unknown 分类可作为后备，但需要可靠的已曝光类别裁剪图库及相似度拒答校准；若 ROI 仍来自 Qwen，就未解决定位依赖。现阶段补齐三类监督比继续换通用 prompt 更直接、可审计，先只推进这一条。
