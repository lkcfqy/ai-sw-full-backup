# 制造质检方案深查：把范围收紧到“换型后装配放行证据核验”

> 本文保留探索过程中的连接器及ChangeGate/KitGate名称。最终单选已统一为四类零件的 **KitGuard**，执行范围与评测协议以[最终方案](./最终方案_KitGuard.md)为准。

调研日期：2026-09-26。此文是独立方向评估，不代表已取得工厂合作、已完成系统或已获得任何测试效果。

## 结论

若制造方向最终入选，建议题目定为 **ChangeGate：换型后装配放行与复检 Agent（변경 대응 조립 검증 AI Agent）**。只做一种免焊连接器组件，解决“图片看着正常，但当前订单所适用的规格版本不同；旧检查结论因此不能放行”的问题。

优先级前提：开赛后的前两天，能取得真实可操作对象、明确规格，以及至少一位愿意核对验收规则的制造/实验室工程人员。如果这些条件均没有，纯用公开缺陷图片包装工单，并不足以比材料核验 Agent 更有获胜把握。

**核心判断：视觉异常检测、主动放大、RAG 检索、自动工单、返工建议都已有人做。竞争点必须变成一个经盲测证明的窄任务：规格变化时，识别哪些检验失效，主动补证，拒绝无证据放行，完成可复核的数字闭环。** 这是竞赛产品定位，不应宣称世界首创或算法首次。

## 最锋利的窄场景

目标对象：桌面上可反复装配、无须上电的连接器及彩色线材。只检查外观可证实的属性：接口数量、线色、插入位置、连接关系；不声称从照片判断电气性能、扭矩、内部接触可靠性。

场景：订单 A 适用规格 Rev.A，订单 B 适用 Rev.B。两份规范只有一个关键属性改变。操作者拿来了外观完整但按旧版装配的对象，或者提交了另一件对象的复检照片。系统必须抓住适用范围、对象身份和证据时序三个问题。

任务循环：

1. **解析订单与规格**：AI 从非结构化说明抽取候选规则，同时保留原文位置和版本；用户确认后规则才进入可执行状态。
2. **形成检查计划**：识别当前证据缺口。已有俯视图看不清接口时，请求特定视角或近照；没有缺口时不增加无效步骤。
3. **视觉观察与确定性核验**：视觉模型只输出观察值及证据区域；规则程序比较数量、位置和版本。无法确认的项目保持“待复检”。
4. **生成纠正任务**：只根据已确认规则指出哪一项不符，建立带对象 ID 的检查/纠正工单。避免臆测工艺根因。
5. **重新检查与放行**：收到新的照片，核验对象、时间、规范版本及全部强制检查项；满足条件后生成待人审核的放行包，记录状态转换。

竞赛演示可以真实执行软件工单与规则核验。操作者按提示改变装配并重新拍照，则复检本身也是实测。没有实际工厂使用时，必须写成“桌面装配实验原型”，不能写“工厂部署”或“减少某企业次品”。

LOCO 原论文的连接器约束包括连接器数量、夹位数量与线色对应、两端相对插接位置等，适合作为“逻辑异常确实是独立难点”的依据。其螺钉袋则含严格的零件种类与数量约束。**这些是数据集设定，不是通用工业规范。** [LOCO 原论文，第 3 节](https://link.springer.com/content/pdf/10.1007/s11263-022-01578-9.pdf)

建议公开数据仅用于视觉模块的小型独立测试。完整 agent 的主要证据来自自采对象和预先写好的实验规范。公开图像不能通过随意配对“异常图片+正常图片”变成真实返工前后数据。

## 有意义的技术贡献边界

工程贡献可以集中在三个可测试机制：

- **变更影响分析**：规则更新后，只使依赖被改变属性的旧检查失效。必须同时测漏失效和过度失效，防止每次全部重检的伪智能。
- **主动取证**：按尚未满足的条件选择下一张必要照片或信息。衡量正确完成任务所需拍照数/人工交互数，并报告无法判断的比例。
- **证据绑定与状态约束**：每个结论绑定对象、规格版本、证据文件与检查结果；关单程序拒绝缺证、旧证或别件证据。

视觉模型和 LLM 使用现有 API 即可。没有 GPU 时完全不把微调、强化学习、数字孪生或机器人集成放入关键路径。规则抽取用结构化结果并经过人工确认；状态转移由代码验证。开放式模型负责解读与计划，不能单凭生成一句“合格”更改放行状态。

最大的硬缺陷是：若规范完全结构化、工件种类固定、视角固定，一个普通规则工具很可能更便宜可靠。项目要承认这个边界，并把比较放在“新版本规范、新订单条件和不完整证据”上；否则 AI 部分只是装饰。

## 评测：必须区分视觉正确与闭环正确

拟定 48 个任务，不是已取得成绩：12 个正常、12 个装配不符、8 个证据不足、8 个版本冲突、8 个旧照片/别件照片/工具失败。任务分布预先固定；至少 16 个保持不参与调试，并包含未见过的组合。若只有少数同件的近似照片，不应称为独立样本。

至少比较三组：同款 VLM 单次判断；人工配置的固定规则工作流；完整系统。三组拥有相同原始照片、规格和订单，公开是否允许补拍以及成本。另做“关闭版本失效机制”和“关闭证据绑定”的消融。

指标包括：完整任务正确率、错误放行数及分母、正常任务被阻塞比例、必需项目漏检数、证据引用正确率、交互次数、端到端耗时和 API 成本。不能只报告一个准确率，也不能通过所有任务拒绝放行得到漂亮安全数字。若小样本观察到 0 次错误，应报告“0/N”，不要宣传零风险。

3–5 名真实使用者可验证可理解性和操作负担；没有制造从业者时，明确是学生/研究人员实验，不当作工厂有效性证据。可在交换顺序的条件下让使用者完成常规检查和 agent 检查，记录时间与错误；样本有限时只做描述性比较。

| 时间 | 展示 | 要让评委看到的判断 |
|---|---|---|
| 0:00–0:20 | 一件外观完整的连接器组件，订单对应 Rev.B，旧合格记录是 Rev.A | 看着完整不代表符合本次要求 |
| 0:20–0:55 | 系统自动找到规范差异，定位必须重检的条件 | 文档更新能影响行动 |
| 0:55–1:25 | 现有照片遮挡一个接口；系统请求特定近照，再指出错接位置 | 主动取证有明确目的 |
| 1:25–2:00 | 人员按确认规则调整装配，先故意提交旧照片，系统拒绝；再提交实际新照片 | 不把一张正常图当修复成功 |
| 2:00–2:30 | 新证据核验通过，生成完整放行包，人工确认，工单状态真实变化 | 工具执行与结果核验完整 |

不用危险真实产线，不用现场动机器人；桌面实物和数字工具闭环足以说明原型能力。不能以人工隐藏操作冒充自动工具结果。

## 八天上限与放弃条件

单人上限：一个对象家族、两个规范版本、三种取证动作、一个本地工单数据库、一个确认界面、48 个以内精心核验任务。2–3 人可以增加真实使用者测试与第二个变更类型，不建议扩成多工厂平台。

赛前仅做调研、需求整理、数据许可和资源确认；按本届规则在正式开发期开展新开发。首日完成规则/数据定义和一个静态检查；第二日必须证明实物图能可靠读出核心观察值，且有人验证规则。否则删除视觉野心，或直接放弃制造为主选题。第三至四日实现主动取证与证据绑定，第五日冻结留出集并跑基线，第六日用户实验，第七日修复与录制，第八日上午完成提交物和可复现核验。

**不选制造的硬条件**：只能使用网上图片、没有可改变并重新拍摄的对象、没有人能判定规则是否合理、核心视觉读取两天仍不稳定。遇到这些情况时，继续扩大 RAG、页面或“多智能体”数量不会补足真实性。

## 追加收敛：桌面套件比连接器更适合无工厂资源的八天版本

综合根任务的具体约束，最终制造候选宜再缩为 **KitGate：订单变更后的桌面套件出库核验 Agent**。使用螺钉、垫片、螺母或积木等廉价物件，加手机和托盘。此版本不需要把取得工厂合作设为开发前提；把产品定位明确写成“小型备料/教学套件实验原型”，用正式赛期内采集的真实物理对象证明闭环。工程人员访谈提升外部有效性，但没有访谈不妨碍诚实完成桌面实验。

它比“公开 VisA 图片+虚构维修链”更强的原因，是补件动作与复拍可真实发生、ground truth 可直接人工清点、盲测可让测试者临时改变订单。不能据此推导工厂误发率下降，真实工业推广仍是下一阶段。

**商业查重的直接反证**：Tulip 的 Laerdal 案例已经包含计算机视觉识别套件部件、核对 BOM、完成后拍照留档及允许发货。因此这个大流程高度同构。项目不能将其称作首个视觉出库闭环。[Tulip/Laerdal 官方案例](https://tulip.co/case-studies/laerdal-medical/)

Tulip Kitting 文档还包含工单选料、组件数量、重复选取阻止、组件谱系与完工状态。其文档明确区分示范用模拟按钮与真实部署流程。[Tulip Kitting 官方文档](https://support.tulip.co/docs/kitting)

竞赛差异可以定位为：在不训练专用检测器的前提下，针对频繁换单、自然语言变更及不完整照片，自动转成可检查约束，要求最小补证，并让旧证据随版本变化失效。这里只是要验证的产品假设；没有直接比较之前，不说性能超过 Tulip，也不根据未核实报价宣称成本优势。

### 视觉风险与第 2 天闸门

“多拍一次”不保证 VLM 计数正确。重叠小物体、近似规格、反光垫片和透视都会使重复调用得到相同错误。复拍必须改变可观测条件：例如要求分开放到带编号格的托盘，每格最多一件，同时用规则/图像工具计数；不是简单让模型再想一次。

第 2 天用 10–15 个遮挡、混料、相似类别难例验证这条交互是否确有改善。记录补证前后错误，不能假设有效。最低版本只支持 4–6 个明显可区分的类别，每类至多 5 件；不凭无标尺照片断言 M6/M8、螺距或材料牌号。视觉仍不稳时降低对象复杂度，而非扩大模型流程。

### 值得留下的技术细节

- 工单版本使用乐观锁：准备放行与实际写入之间如果订单改变，写入必须失败并重新检查，避免演示只处理提前发生的变更。
- 对“撤销旧放行”定义清楚：撤销软件中的出库授权并重开检查；已实际发出的货物无法靠软件撤回。
- 写回后回读状态，注入一次存储失败/版本冲突，验证不能展示虚假成功。
- 对重复文件以哈希查重；新的照片配对象 ID 与本轮取证码。它们帮助操作追溯，但不能证明照片无法伪造，亦不能绝对认证物理对象身份。
- 同一款视觉模型、同样输入条件比较三组系统。固定结构化 BOM 下规则工具可能最好；项目价值必须主要来自未见变更的转录负担、缺证交互和状态正确性。

**最终方向判断：值得作为强竞赛候选继续收敛，可以在八天完成可信原型；目前没有足够证据承诺第一。它的上限来自实物现场挑战与公开的失败处理，下限来自计数不稳、人工排好格后 AI 贡献不清，以及把厂商早已实现的能力说成原创。**
