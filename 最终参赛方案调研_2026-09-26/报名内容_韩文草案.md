## 프로젝트 소개 초안

### 개발 배경 및 목적

소량·다품종 작업에서는 주문별 부품 구성과 작업지시가 변경될 수 있다. 이때 이전 주문을 기준으로 확인한 결과를 재사용하거나, 가림·흐림이 있는 사진을 근거로 수량을 확정하면 부품 누락과 잘못된 완료 처리가 발생할 수 있다. 본 과제는 작업지시 변경을 구조화하고, 증거가 부족할 때 필요한 재촬영이나 부품 분리를 요청하며, 보충 후 실물과 현재 주문을 다시 검증하는 AI Agent 개발을 목표로 한다.

### 주요 기능

1. 주문 및 자연어 변경 지시를 해석하여 수량·품목 차이를 제시하고, 담당자가 확인한 변경 버전을 관리한다.
2. 스마트폰 사진과 기준 부품 정보를 관찰하고, 필요한 경우 특정 영역 재촬영 또는 겹친 부품의 분리 배치를 요청한다.
3. 누락·과다·오배치가 확인되면 보충 작업을 안내하고, 새로운 사진으로 결과를 다시 검증한다.
4. 현재 주문 버전과 검증 근거를 확인한 뒤 실험용 작업지시 상태를 기록하고, 저장 결과를 재조회한다. 주문 변경이나 저장 실패 시 이전 결과를 완료 상태로 오인하지 않도록 처리한다.

### 적용 범위 및 기대효과

초기 범위는 외관상 구분 가능한 네 종류의 부품, 품목별 최대 세 개, 총 열두 개 이하의 탁상형 키팅 작업으로 한정한다. 작업자는 실제 부품을 이동하고 최종 결과를 확인하며, Agent는 다음 확인 행동을 선택하고 도구를 실행한다. 실제 공장 배포 성과를 가정하지 않고, 통제된 실물 실험에서 오류 완료 여부, 작업 완료율, 재촬영 횟수, 소요시간을 측정하여 효과를 평가할 예정이다.

## 활용 기술 및 개발 환경

- AI: 로컬 실행이 가능한 기존 비전 언어 모델을 우선 사용한다. Qwen3-VL-8B-Instruct와 4B-Instruct를 후보로 하며, 개발 초기에 동일한 사진으로 정확성·지연시간·메모리를 평가한 후 모델과 설정을 고정한다. 구조화된 행동 출력을 검증한 뒤 프로그램 도구를 호출한다.
- 개발: Python 기반 API 서버, 경량 웹 화면, SQLite 상태 저장, 이미지 업로드·영역 추출 도구.
- 검증: 구조화된 주문 제약 검사, 증거와 주문 버전의 연결, 상태 변경 시 버전 검사, 저장 후 재조회.
- 장비: MacBook Pro M5 Pro / 64 GB, i9-9900KF·RTX 3080 10 GB·RAM 32 GB 데스크톱을 보유하고 있다. 실제 부품 네 종류와 번호 트레이를 준비할 예정이다. 사진 입력은 Mac 카메라부터 검증하고, 사용 가능한 경우 스마트폰 업로드도 활용한다.
- 추론: Mac 단독 시연을 목표로 하며, 데스크톱은 비교 평가 또는 예비 추론에 활용한다. 신규 모델 학습·추가 GPU 구매·유료 외부 API를 필수 전제로 하지 않는다. 로컬 성능과 오프라인 실행 가능 여부는 개발 기간에 실측한다.
- 개발 보조: Codex Pro 20x를 코딩·테스트·문서 작성 보조에 활용하고, 사용 범위와 기존 자산을 대회 규정에 따라 공개한다. 참가자가 실제 실험, 결과 검토 및 제출 내용을 책임진다.
- 기존 자산: 사용 모델·라이브러리·공개 자료를 출처 목록에 기록한다. 본 대회 신규 개발분은 Agent 행동 선택, 증거·버전 관리, 도구 실행 흐름, 화면 및 실험 데이터·평가 절차로 구분한다.
- 제약: 치수·나사산·재질을 일반 사진만으로 판정하지 않으며, 실제 생산설비 제어나 자동 출하와 연결하지 않는다.

## 개발계획 초안

### 개발 방법

하나의 Agent와 명시적인 작업 상태를 사용한다. AI는 주문 해석 및 증거 부족 상황에서 다음 행동을 선택하고, 수량·버전·기록 일관성은 별도 프로그램으로 확인한다. 재촬영 후에도 정보가 부족하면 수량을 추측하지 않고 수동 확인 상태를 유지한다. 다만 수동 전환만으로 오류율을 낮추는 것을 방지하기 위해 정상 작업의 완료율과 불필요한 중단도 함께 측정한다.

### 정량 평가 계획

- 개발용 16개 상황과 분리된 평가용 48개 상황을 계획한다. 실제로 촬영한 사진과 주문·도구 이벤트의 오프라인 재생 평가이며, 동일한 물체 배치의 여러 사진을 독립 사례로 중복 계산하지 않는다. 실시간 사용자 작업 결과와 구분하여 보고한다.
- 정상, 누락, 과다·오품목, 가림·흐림, 주문 변경, 도구 실패 상황을 포함한다.
- 수기 체크리스트, 번호 트레이와 규칙 검사, 동일 모델·도구를 사용하는 일반 Agent와 비교한다.
- 평가 목표: 테스트 내 잘못된 완료 처리 0건, 명확한 정상 사례 12개 중 10개 이상 완료, 사전에 해결 가능하다고 분류한 이상 사례에서 올바른 완료율 80% 이상, 주문 변경 사례에서 이전 버전 결과 사용 차단. 수동 판정으로 넘긴 해결 가능 사례는 완료로 계산하지 않는다. 이 수치는 개발 목표이며 달성 결과가 아니다.
- 시간 단축 목표는 수기 방식 대비 중앙값 20%로 설정하되, 오류가 악화되지 않는 조건에서 검증한다. 모든 사용자의 작업·보충·확인 시간과 추론 지연시간을 포함하여 보고하고, 외부 API를 사용한 경우 그 비용도 공개한다.
- 가능하면 자발적 참여자 6명이 수기 체크리스트, 번호 트레이·규칙, KitGuard의 세 가지 방법으로 서로 다른 유사 난도 작업을 한 번씩 수행하도록 하여 총18회의 실제 상호작용 작업을 평가한다. 순서를 바꾸어 학습효과를 줄이며, 시간 절감은 이 실험에서 측정한다. 실제 참여 인원과 실패 사례를 그대로 공개한다.
