# 独立候选与反证

调研日期：2026-09-26。任务：在普通电脑、模型 API、校园可接触用户的约束下，独立检验是否有比泛化申请材料审查或公开图片质检工单更强的选题。以下排序是研究判断，不是官方评分，也不是获奖概率。

## 最终判断

在本轮新增候选中，优先选择**版本变更下的桌面套件备料与复核 Agent**，而不是继续扩大校园材料助手的功能。该方向能在八天内产生真实物体、真实纠错、真实用户操作的可核验记录，适合三分钟现场演示，也更直接回应制造场景。

应准确称为“桌面真实实验原型”，没有工厂合作就不称“工厂 Pilot”“生产级放行系统”。它的胜算来自可审查的完成度与实验，不来自题目首创。以下为它必须正面面对的竞争事实。

## 桌面备料方案的直接竞品

| 已有方案 | 官方已公开的能力 | 对本项目的约束 |
|---|---|---|
| Tulip Kitting | 核对库存、工单需要的物料、重复领取；生成标签及追溯记录 | 缺件检查、工单与留痕本身没有新颖性 |
| Cognex In-Sight ViDi Check | AI 检测部件，按照预定义布局核验套件或装配 | “用 AI 看零件是否齐全”不是技术首创 |
| LightGuide | AR 指导、AI 视觉验证、传感器与流程逻辑、阻止错误进入下一步骤 | “识别—指导—复核闭环”也不是空白市场 |

主来源：

- [Tulip 官方 Kitting 文档](https://support.tulip.co/docs/kitting)
- [Tulip 官方 Kitting 产品页](https://tulip.co/digital-guidance/kitting-software/)
- [Cognex 官方 ViDi Check 产品资料页](https://www.cognex.com/en-be/downloads/literaturemain?event=5989dc6f-1dc2-4159-8970-2a47528b3e7f)
- [LightGuide 官方平台说明](https://www.lightguidesys.com/)

因此建议把项目贡献写成**低硬件门槛下，针对变更频繁的少量套件，把非结构化变更转换为可核验约束，并在证据不足时主动补证、在版本变化时撤销旧结论**。这些是本次实现和评测重点；未测试前不能宣称比商业产品更好、更便宜多少，不能断言竞品没有这些能力。

### 最小可行边界

- 四至六类外观能稳定区分的材料。可以用不同颜色与形状的教学套件；如果采用紧固件，不能承诺仅凭普通照片识别 M3/M4 等尺寸差异。
- 顶视手机、普通灯光、纸质定位板。对堆叠与遮挡主动请求“展开并重新拍照”。必要时用标尺、条码或人工读数提供额外证据，不能让 VLM 猜测隐藏数量。
- 自由文本/表格 BOM → 人工确认机器可执行约束 → 拍照 → 错误或证据不足 → 最小纠正任务 → 复拍 → 独立约束核验 → 版本绑定的复核记录。
- BOM 更新后，旧照片不一定毫无价值，但旧“全部通过”结论必须失效；仅重新检查受影响约束可作为进阶项，不要在八天内实现复杂完整的工业配置管理。
- 模型的自报置信度不是客观可靠性证明。拒绝放行应依据缺失字段、图像质量、目标遮挡、识别冲突或未满足的明确约束。

### 能证明 Agent 价值的测试

必须有“槽位清单/条码＋规则”的强基线，不能只与聊天 RAG 比。固定规则很可能在固定 BOM 与固定槽位上更便宜、更快；应如实报告。

重点测试未用于开发的新 BOM、自然语言变更、歧义要求、多余/缺失件、遮挡、旧证据重用与工具失败。比较：

1. 错误套件被标为通过的数量与比例；
2. 真正完成正确套件所需总时间，包含拍照、追问和复核；
3. 版本更新后错误沿用旧结论的次数；
4. 新 BOM 配置所需人工时间；
5. 正常套件被无谓阻断的比例。

如果 Agent 只提升“理解新变更的配置效率”，而不比规则系统更快，结论就限定在该收益上。五位同学属于小样本可用性实验，可报告每人结果与范围，不能推算工厂普遍降本比例。所有测试图像、BOM、真值与失败样例保留，留出至少一组完全未参与调试的套件配置。

## 独立候选一：昌原校园无障碍路线动态恢复 Agent

闭环可设为：读取用户行动约束 → 从人工核验的校园路网求路径 → 收到临时封路照片 → 请求位置/时间/第二视角以核实 → 更新有有效期的障碍记录 → 重规划 → 用户到达回执验证。

真实资料入口存在：昌原大学公开了障碍学生支持中心、设施支持与辅助设备借用安排。[学校 2025 年个人教育支持计划](https://www.changwon.ac.kr/material/na/ntt/selectNttInfo.do?mi=5265&nttSn=1366468)。这只能证明存在联系渠道，不能证明用户已取得协作，也不能证明校园目前有特定无障碍缺陷。

主要反证：

- [Google 官方介绍](https://blog.google/products-and-platforms/products/maps/introducing-wheelchair-accessible-routes-transit-navigation/)已长期提供部分公共交通无障碍路线。
- [Wheelmap 官方介绍](https://news.wheelmap.org/en/about-wheelmap/)已提供公众协作的无障碍地点资料。
- [Amsterdam 官方 AI 团队开源实现](https://github.com/Amsterdam-AI-Team/Accessible_Route_Planning)已支持按人行道宽度、路缘高度等偏好规划路线。
- [Project Sidewalk 官方代码库](https://github.com/ProjectSidewalk/SidewalkWebpage)已整合众包与机器学习来采集、核验无障碍特征。
- [OmniAcc 原论文](https://arxiv.org/abs/2509.07220)已研究生成式 AI 与无障碍交互导航。

**结论：不选作默认方案。** 地方实测可能有很强感染力，但八天内能否取得行动不便用户的真实协作未知；人工采集完整安全路网也会占据核心时间。不能以健全同学走通替代轮椅使用者真实可达性，更不能把 VLM 看照片当作安全通行保证。若已有支持中心和真实用户协作，其优先级才可能超过桌面备料。

## 独立候选二：可核验的 AI 实验复现/失败恢复 Agent

闭环可设为：读取实验代码与目标 → 在受限环境运行 → 分析失败 → 修复 → 独立测试 → 导出环境、数据与结果清单。用小型 CPU 数据集可避免 GPU 与工厂依赖，校园研究生也容易理解价值。

主要反证：

- [AIDE 官方代码库](https://github.com/WecoAI/aideml)已公开自主生成、调试和评测机器学习代码的代理。
- [Weco 官方文档](https://docs.weco.ai/)已面向代码优化、模型与代理场景提供相关能力。
- [CORE-Bench 原论文](https://arxiv.org/abs/2409.11363)已专门研究计算复现代理基准。
- [MLAgentBench 原论文](https://arxiv.org/abs/2310.03302)已建立机器学习实验代理评测。

**结论：不选作本届默认方案。** 它适配博士背景，但普通“日志—修复—运行”容易成为现成编码代理的包装；要形成强于这些系统的可复现技术贡献，需要更长周期。对综合应用竞赛而言，桌面套件的现场结果更直接，失败与纠正也更容易被非该研究领域的评委核实。

## 对最终选题的建议

冻结桌面备料这个单一场景。不要为了显得宏大再加机器人、数字孪生、ERP、声纹、人脸、预测维护或一串代理角色。让评委随机拿走一个物件、换一份 BOM、再拿来旧照片，系统能识别哪些证据仍有效、哪些必须重做，并且最终由真人把真实套件修正正确。这种可被当场挑战的可靠性，比声称“全面赋能制造业”更值得投入。
